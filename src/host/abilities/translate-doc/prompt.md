任务：把 Markdown 文档【${target}】翻译为简体中文，并把译文写入【${docPath}】。源文档是其他语种（宿主已校验源文不是简体中文），目标语言固定为简体中文。

【模式】${mode}
${modeHint}

【边界】
只处理这一篇文档，只写这两个目标文件（译文，以及仅在确实出问题时写的一个台账文件）；绝不翻译或修改任何其它文件。

【固定参数（原样使用，禁止改写，禁止按当前目录自动推导）】
源文档 SRC = ${target}
译文文档 DOC = ${docPath}
源码路径键 KEY = ${targetKey}

【输出预算铁律（违反即任务失败）】
- 绝不在思考/推理里书写译文正文；思考只用于规划章节顺序与术语取舍。
- 每次回答都必须先发出工具调用，再写不超过一句的说明。
- 译文必须分段落盘：每段译文放进当次工具调用的参数里，不要积攒到一次写完——长文档一次写完会耗尽输出预算，导致本轮没有工具调用、产物不落盘、任务直接失败。分批粒度由你按自己的输出预算决定（见步骤 3）。

【步骤】
1. 用读文件工具读取 SRC 全文（frontmatter 与正文都要看）；读不到就报告失败并停止。
2. 先写骨架：用写文件工具把下列内容写入 DOC（UTF-8），其中最后一行锚点原样保留：

   ---
   源码路径: ${targetKey}
   层级: ${layer}
   生成时间: ${generatedAt}
   ---

   # ${srcName}（中文译文）

   **路径**：${targetKey}

   <!-- FS_TRANSLATE_CURSOR -->

3. 分段翻译：按源文档的章节/段落顺序分批翻译，每批一次工具调用，用编辑工具把锚点行 `<!-- FS_TRANSLATE_CURSOR -->` 替换为「本批译文 + 空行 + 同一个锚点行」。
   - **每批翻译多少、总共分几批，由你自己判断**：看你的单步输出预算与源文长度——预算宽裕就一次多译、批数少一些（步数越少越省），预算紧张就少译多批。唯一红线是「不要让本批译文长度逼近单步输出上限」（一旦逼近就拆成两批）；也不必为保险把每批压得过小。
   - 每批译完立刻落盘，再开始下一批；不要在思考里攒完整篇译文再一次性落盘。
   - 忠实翻译：不增删内容、不改义；标题/列表/表格/引用/链接结构一一对应；frontmatter 键名不翻译。
   - 特殊名词（专有名词、技术术语、产品名、API/命令/包名）首次出现保留原文并就地写「原文（中文解释）」，如 CRLF（回车换行）、WebSocket（全双工通信协议）；同篇再次出现直接用原文，不重复解释；普通英文词按含义翻译，不给变量名/局部变量/普通英文词加（中文）括号。
   - 代码块、行内代码、文件路径、URL 保留原文不翻译；代码块内注释可翻译，代码本身不变。
4. 收尾：最后一批译完后，用编辑工具把残留的锚点行 `<!-- FS_TRANSLATE_CURSOR -->` 整行删除，使文档以译文结尾。
5. 逐条验收：DOC 前四行是 frontmatter（源码路径 / 层级: ${layer} / 生成时间）与空行；标题为「${srcName}（中文译文）」；正文结构与源文档一一对应；无锚点残留、无占位字样；全程只产出这一个文档文件。

【已知坑，务必规避】
- frontmatter 的「生成时间」必须用上面给的值原样照抄，不要自己编造时间。
- 不要把译文写进思考里；不要把整篇译文攒到最后一次写完。
- 不要保留锚点或占位字样，也不要保留源文档的原文段落。
- 不要把译文写成摘要或改写：逐段对应原文。

  ## 复验（如何确认已解决）
  确认「这次不会再犯」的核验方式。

- 本轮一切顺利时，**不要**写任何台账文件。

【汇报（只说这些）】
