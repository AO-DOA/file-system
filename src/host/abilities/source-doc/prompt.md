任务：为【${target}】这一个源码文件写源码层（L3）逐行中文注解。产物文档 DOC 由**宿主**构建并写入，你只填骨架、**不要写 DOC**。

【模式】${mode}
${modeHint}

【边界】
只注解这一个文件；绝不批量为其它文件生成第二篇。

【固定参数（原样使用，禁止改写，禁止按当前目录自动推导）】
目标文件 TARGET = ${target}
产物文档 DOC = ${docPath}
源码路径键 KEY = ${targetKey}
骨架文件 SKELETON = ${skeletonPath}
工作目录 CWD = ${cwd}
骨架行数 = ${skeletonLines}

【骨架是填空题（宿主已落盘到 SKELETON，不注入本提示词——体量大）】
- **锚点统一规则（务必照做，能一次避开四类返工）**：每次 `edit` 的 `old_string` 取
  「该单元的**标签行整行原文**（`@行 [N]`；块单元是 `@块 [N-M]（注释块，合并为一条注解）`——**后缀不能省**；
  `@摘要` 段取 `@摘要（…）` 行）起，到该单元的 `注解: ` 空位行为止」的**整段原文**，按 read 到的实际内容原样拼。
  标签行在骨架里唯一，因此：① 块内裸源码行不带 `代码: ` 前缀、② 重复代码行不会让锚点匹配到多处、
  ③ 不必按「`@块` 行号 + 1」推算注解行位置、④ 块标签带固定后缀、按 `@块 [N-M]` 截断会匹配不到
  —— 这四类都实测返工过，用「整行标签 + 到空位行」的整段锚点即可全部避开。
- 结构：文件头说明 + `@摘要` 段 + 若干单元。每个单元形如：

      @行 [N]                 ← 或 `@块 [N-M]（注释块，合并为一条注解）`
      代码: <源码原文>
      注解:                   ← 空位，等你填

- **多行注释块只有首行带 `代码: ` 前缀**，块内其余行是**裸源码行**；`@摘要` 段**没有 `代码: ` 行**，
  只有 `@摘要（…）` 提示行 + 一行 `注解: `。
- 每个单元的注解行紧跟该单元**最后一个** `代码: ` 行之后，**位置随块内行数变化**（不要按行号推算）。
- 你只填每处「注解: 」**之后**的内容；`@行`/`@块` 的行号与 `代码: ` 行由宿主保证，一个字都不要改。
- `@摘要` 段：在它下面的「注解: 」后填一句话（这页代码解决什么问题），可留空。
- 骨架很长，用 read 读 SKELETON；读不完就用 offset/limit 分段读，先摸清单元边界再动手填。
- `edit` 逐条执行并各自容错：某条 `old_string` 匹配失败，只重读骨架重拼那一条，不要中断整批。

【步骤】
1. read 骨架 SKELETON（共 ${skeletonLines} 行），弄清单元顺序与边界；大骨架用 offset/limit 分段读。
2. 仅当【模式】为「更新」时：先读现有文档 DOC 作基线，保留其中仍然正确的措辞。
3. 用 edit **分批**把注解填进骨架，**每批 ≤20 个单元**，每批单独一步：read 该批区段 → 一个程序只做这一批的 edit → 再做下一批。
   不要把多个批次的 edit 塞进同一个程序；**不要用 write 整篇重写骨架**（骨架约为源码全文的 1.5 倍，一次写完必然耗尽输出预算）。
4. 填 `@摘要`。
5. 按【验收】逐条核对。

【填注解要求（模型主干）】
在每处「注解: 」后写该行/该块在干什么的中文解释；只填语义，不改行号与代码行；严格逐单元，一条单元只写它自己的释义（块头行与其内部形参是不同的独立单元，不得合并边界）：
- 首次出现的英文术语/名称就地写「English（中文）」，如 Run（运行单元）、esbuild（打包器）、createRequire（创建 require 函数）；
- 变量名/局部变量（ctx、i、m）、普通英文词、JS 关键字不加（中文）括号；
- 全简体中文，代码/路径/专有名词保留原文；不编造，不确定写「推测：…」。

【验收】
骨架文件里每个「注解: 」后都有中文释义（至少每条单元都填到，不空转）；
`@摘要` 已填或明确留空；行号与 `代码: ` 行与你读到的一致（你一个字都没改）；
DOC 与 index.json 由宿主生成，你不要手写（DOC 只用于更新模式作基线，产物以宿主构建结果为准）。

【已知坑，务必规避】
- 本层**没有** skill / bash 工具：不要尝试加载技能或运行任何脚本，也不要提任何脚本命令。
- 不要写 DOC、不要手写或改写 frontmatter（含「生成时间」）、不要写 index.json——全部由宿主负责。
- 不要改动骨架里的行号与 `代码: ` 行；不要新增/删除单元，不要调整单元顺序。
- **分批是硬约束**：一次程序里塞太多 `edit`（或多批合一）会撞单步输出上限（实测 `turn/end reason: max-tokens`），
  整轮一个写操作都发不出去 → 任务被判「未填写任何注解」而失败。每批 ≤20 个单元、一批一步、批间不要合并。
- **每次回答必须先发工具调用再写解释**：长篇推理会挤掉输出预算，造成空转（无工具调用却结束）。
