4. 用写文件工具把「骨架原文 + 三处语义填充」整篇写入 DOC（UTF-8）。
5. 按【验收】逐条核对。

【正文只填四处】
(a) 标题后一句话职责（替换骨架里的 `> <一句话说明这个文件夹是干什么的>`），再写 1–2 句**总体角色说明**（替换骨架里 `<1-2 句总体角色说明…>` 那一行）。
    **这里只讲整个目录**在项目里扮演什么角色，保持精简；**不要**在此逐项展开子目录/文件各自的职责（那些在下方子目录表、文件表与目录树注释里，展开会与它们重复）。
(b)「子目录」表：列出**第一层子目录**及其作用（一行一个，如 `| file-doc/ | 生成文件摘要（L2）能力 |`）。
    **「不递归」指不深入子目录的子目录**——不列更下层，但要逐项分析第一层子目录本身是做什么的；
    子目录名可从目录树得知，再读每个子目录内容（README.md / 首层文件抽样 ≤30 行）判断作用；没有子目录则写一行「无」。
(c)「文件」表每个文件一行职责；
(d) 目录树里**每个节点后**的 `# <作用>` —— 逐个换成「这个文件/子目录是做什么的」的一句话
    （如 `├── file-doc/  # 文件摘要（L2）能力`）。
    只替换 `# <作用>` 这六个字符，**不要改动树结构、项名称、缩进与 `├──`/`└──` 连字符**。
全简体中文；不编造，不确定写「推测：…」。
