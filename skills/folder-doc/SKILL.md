# /folder-doc — 目录概览（L1）

> **版本**：1.0

**目标是一个文件夹**（宿主点选/指定的那一个），为它生成**一份**「目录概览」md，写入 `<书库根>/目录概览/`，并维护 index.json「目录层」一条记录。

文档描述这个文件夹在项目里的角色，只列它**直接**包含的子目录/文件（**不递归、不逐个子文件夹生成文档**）。子文件夹在「子目录表」里一行概述即可，不展开其内部。

**契约（宿主已定死，技能遵守即可）**：
- **书库根**：`$DSH_HOME/books/<projectKey(项目根绝对路径)>/`（集中模型，桶名算法与 DSH format.ts 一致，无 `<项目名>-book` 中间层；见 docs/book-store-decisions.md）。宿主任务 prompt 会给 `--book <书库根>`——传了就用它（兼容旧调用）；未传则脚本自动推导新桶（推荐传 `--root <项目根绝对路径>`，脚本也能从旧 `<root>/.book/<名>-book/` 反推项目根）。
- **源码路径键**：`工作区名 + '/' + 相对工作区根的路径`（目标即工作区根时为工作区名本身）。这是 frontmatter「源码路径」与 index.json「目录层」的键。
- **只生成这一个文件夹**，一次一篇，绝不批量。

**模型负责语义，脚本只兜底确定性**：模型读线索 → 填语义（职责判断、子项职责、目录树行尾简介）；脚本 `folder-doc.mjs gen` 负责 frontmatter（源码路径/层级/生成时间）、目录树（`gen-tree.sh`）、index.json upsert。无骨架、无递归多文档。

## 第零步：定位（先查事实，再列清单）

1. 读任务 prompt 确认**书库根 `--book`**（未给时确认项目根，脚本用 `--root <项目根绝对路径>` 自动推导新桶）与**目标文件夹**（宿主已给）。
2. 确认目标文件夹的存在与直接子项：`node scripts/folder-doc.mjs gen <目标文件夹> --book <书库根> --key '<源码路径键>' [--root <项目根绝对路径>] [--name <文档名>]` 会生成一篇（frontmatter+目录树+index upsert；未传 `--book` 时脚本自动 = `$DSH_HOME/books/<projectKey(项目根)>/`）。
3. 命名：目标文件夹 → `<文件夹名>.md`（目标即工作区根 → `<工作区名>.md`）。
4. **检查 → 再列清单 → 后执行**。先探查（读目标文件夹、确认书库根），再 `todo_write` 编排，执行中与真实不符就改计划。

## 第一步：目标与排除

1. 目标文件夹 = 宿主指定的那个目录（一个）。
2. **不递归**：子文件夹不单独生成文档，只在「子目录表」里一行概述。
3. 排除（不列出）：`.git` `node_modules` `__pycache__` `.venv` `venv` `dist` `build` `out` `target` `.next` `.cache` `vendor` `.idea` `.vscode` `.book`，以及二进制/图片/锁文件/压缩包/>1MB 文件。

## 第二步：读线索（目标文件夹）

按优先级读，能推断就停，不贪多：

1. **元数据**（优先）：目标文件夹自身的 `README.md` 及变体、`package.json`（name/description）、`pyproject.toml`、`Cargo.toml`、`go.mod`
2. **文件夹名约定**：`src`=源码、`docs`=文档、`tests`=测试、`scripts`=脚本、`examples`=示例、`assets`=资源……
3. **子项名称**：直接子文件/子文件夹名往往足以推断职责
4. **抽样源码**：仅当以上不够时，读 1-2 个关键文件开头 30-50 行
5. **不读内容**：二进制、图片、锁文件、压缩包、>1MB 文件——按扩展名与名称判断

## 第三步：生成与索引

1. **生成**（模型主干）：目标文件夹一份完整 md，参照 `<技能根>/templates/folder.md`。三处填语义——（a）标题后 `> <一句话职责>` 与 2-4 句补充；（b）「子目录」「文件」两张表**每行**（每个直接子项）一句职责；（c）第一层目录树行尾 ` -- 一句话简介`。目录树用 `bash scripts/gen-tree.sh <目标文件夹绝对路径>` 取真实子项，**整段必须包在 `` ``` `` 围栏内**（裸多行会被 Markdown 折成一行，树形结构消失）。frontmatter **源码路径** = 源码路径键（见契约）；**生成时间**由脚本写、每次生成刷新为当前时间——读者据此判断这份解析是否已与文件夹实际内容脱节，模型不要手写或改写它。写入 `<书库根>/目录概览/<文档名>.md`。
2. **索引**：写完 md，跑 `node scripts/folder-doc.mjs gen <目标文件夹> --book <书库根> --key '<源码路径键>' [--root <项目根绝对路径>] [--name <文档名>]`。脚本渲染 frontmatter（源码路径=键/层级=目录/生成时间=本次生成时刻）+ 目录树，写入文档，并 upsert index.json「目录层」一条（保留「文件层」等其它数组不动；「项目根」字段写项目根绝对路径）。**`--content` 是整篇文档替换**：frontmatter（源码路径/层级/生成时间）、目录树、正文全部由传入内容决定，脚本不再渲染任何一部分。仅当你已写好**含完整 frontmatter 与目录树**的整篇文档时才传它；否则**不要传**（不传时脚本才渲染 frontmatter + 目录树）。若 `--content` 的值以 `.md` 结尾且是已存在文件，则脚本读该文件内容整篇写入（兼容「先落盘正文再回灌」用法）。

## 第四步：汇报

1. 文档写完即落盘。
2. 汇报：目标文件夹、生成的文档路径、索引更新情况、推测性描述列表。

## 第五步：问题记录（自检）

先做实质判断——**这轮是否顺利，有没有值得沉淀给技能的坑**（不顺利就见招拆招后记下）。常见如脚本报错、参数不生效、返工、产出不符预期、路径失效、判断失误等，但**不限于此**——只要是这轮暴露出的、下次可能再踩的，就按 `plugins/dsh-plugin-file-system/issues/_template.md` 记一条到 `issues/<date>-<序号>-<slug>.md` 并更新 `issues/README.md` 索引表。**顺利则跳过，保持零噪声**。

## 注意

- **宿主内置实现**：宿主「文件」页签的目录概览按钮为内置实现（不依赖本技能，见插件 README）；本技能供会话内人工调用/复用。
- 同名文档直接覆盖；全简体中文，代码/路径/专有名词保留原文；目标内含 `.book` 则跳过。
- **不递归**：一次只做一个文件夹、一份文档；用户要多个文件夹 → 分别调用本技能，一次一个。
- 脚本与模板随本技能目录分发：`scripts/folder-doc.mjs`、`scripts/gen-tree.sh`、`templates/folder.md`，可随包迁移。
- 模型不要手写 frontmatter（源码路径/层级）与 index.json 的「目录层」结构——索引统一由脚本生成。
- 描述要具体（"Claude Code 钩子配置的桥接插件"），不要"一些代码文件"；不编造，不确定写"推测：……"。
- 与 file-doc 分工：folder-doc 讲"这个文件夹在项目里是什么角色"（L1），file-doc 讲"这个文件干什么"（L2）；同名文档分放 `目录概览/` 与 `文件摘要/`，不冲突。
