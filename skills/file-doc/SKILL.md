# /file-doc — 文件摘要（L2）

> **版本**：1.0

**目标是一个文件**（宿主点选/指定的那一个），为它生成**一份**「文件摘要」md，写入 `<书库根>/文件摘要/`，并维护 index.json「文件层」一条记录。

这篇文档是**微型文章**，回答"这一页代码是干什么的、怎么实现的、为什么这么设计"——读者可以对这个项目一无所知。它**不是**导出清单，也不是逐行注解（逐行注解归 L3 source-doc）。

**契约（宿主已定死，技能遵守即可）**：
- **书库根**：`$DSH_HOME/books/<projectKey(项目根绝对路径)>/`（集中模型，桶名算法与 DSH format.ts 一致，无 `<项目名>-book` 中间层；见 docs/book-store-decisions.md）。宿主任务 prompt 会给 `--book <书库根>`——传了就用它（兼容旧调用）；未传则脚本自动推导新桶（推荐传 `--root <项目根绝对路径>`，脚本也能从旧 `<root>/.book/<名>-book/` 反推项目根）。
- **源码路径键**：`工作区名 + '/' + 相对工作区根的路径`（目标即工作区根时为工作区名本身）。这是 frontmatter「源码路径」与 index.json「文件层」的键。
- **只生成这一个文件**，一次一篇，绝不批量。
- **md/markdown 不生成 L2**（宿主 isMdPath 拒绝）。

**模型负责语义，脚本只兜确定性**：模型写正文（痛点/核心概念一句话/主线走查/导出速查）；脚本 `file-doc.mjs gen` 负责 frontmatter（源码路径/层级/生成时间）、自动命名、index.json「文件层」upsert。

## 第零步：定位

1. 读任务 prompt 确认**书库根 `--book`**（未给时确认项目根，脚本用 `--root <项目根绝对路径>` 自动推导新桶）、**目标文件**、**源码路径键**（宿主已给）。
2. 命名由脚本自动算（完整相对路径前缀，必然不重复），模型不手算。

## 第一步：分析这个文件（读什么）

1. **通读全文**（文件层文档是核心产出，值得读完整；>800 行分段读）。
2. **找上下游**：谁引用它（项目内 grep 导入）、它引用谁（读文件头 import 区）。
3. **提炼核心概念**：这个文件所有代码合起来只干哪一件事——一句话，不允许并列多项（多项说明没提炼到底）。
4. **定主线顺序**：按调用/依赖关系排序导出（被依赖的先讲），不是按文件出现顺序。
5. **收集设计动机**：每个导出的 JSDoc/注释里"为什么"信息。

## 第二步：生成（gen）

1. **写正文**：按 `<技能根>/templates/file.md`（微型文章：解决什么问题 → 核心概念一句话 → 主线走查 → 在整体中的位置 → 导出接口速查附录）。
   - 核心概念必须是一句话本质；主线顺序=依赖顺序（被依赖先讲）；每个主线条目必须有"为什么这么设计"（真实动机优先，没有则写"推测：……"）。
   - 术语在主线中自然解释，**不单独列术语表**；导出接口表来自真实代码，逐个核对不凭名字猜。
   - 全简体中文；代码/路径/专有名词保留原文；不编造，不确定写"推测：……"。
2. **落盘 + 索引**：跑 `node scripts/file-doc.mjs gen <文件绝对路径> --book <书库根> --key '<源码路径键>' [--root <项目根绝对路径>] [--content <正文>]`（未传 `--book` 时脚本自动 = `$DSH_HOME/books/<projectKey(项目根)>/`）。脚本生成 frontmatter（源码路径/层级/生成时间）+ 文档名（完整相对路径前缀）+ 写入 `<书库根>/文件摘要/<名>.md` + upsert index.json「文件层」一条（保留其它数组不动；「项目根」字段写项目根绝对路径）。用 `--content` 传入已写好的正文，脚本前置拼 frontmatter 并剥掉正文里自带的旧头，只兜命名/frontmatter/索引；「生成时间」= 本次生成时刻，重新生成即刷新。

## 第三步：汇报

1. 文档写完即落盘。
2. 汇报：目标文件、生成的文档路径、索引更新情况、推测性内容列表。

## 第四步：问题记录（自检）

先做实质判断——**这轮是否顺利，有没有值得沉淀给技能的坑**（不顺利就见招拆招后记下）。常见如脚本报错、参数不生效、返工、产出不符预期、路径失效、判断失误等，但**不限于此**——只要是这轮暴露出的、下次可能再踩的，就按 `plugins/dsh-plugin-file-system/issues/_template.md` 记一条到 `issues/<date>-<序号>-<slug>.md` 并更新 `issues/README.md` 索引表。**顺利则跳过，保持零噪声**。

## 注意

- **宿主内置实现**：宿主「文件」页签的文件摘要按钮为内置实现（不依赖本技能，见插件 README）；本技能供会话内人工调用/复用。
- 同名文档直接覆盖；全简体中文；目标内含 `.book` 则跳过。
- **不批量**：一次只做一个文件、一份文档；用户要多个文件 → 分别调用本技能，一次一个。
- 脚本与模板随本技能目录分发：`scripts/file-doc.mjs`、`templates/file.md`，可随包迁移。
- 模型不要手写 frontmatter（源码路径/层级/生成时间）与 index.json 的「文件层」结构——索引统一由脚本生成。
- 与 folder-doc/source-doc 分工：folder-doc 讲"文件夹的角色"（L1），file-doc 讲"文件干什么 + 为什么这么设计"（L2），source-doc 逐行注解（L3）；同名文档分放 `目录概览/`、`文件摘要/`、`源码注解/`，不冲突。
