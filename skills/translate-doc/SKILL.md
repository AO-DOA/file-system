# /translate-doc — 文章翻译（中文译文）

> **版本**：1.0

把**这一篇**项目内 Markdown 文档翻译为**简体中文**，产出**一份**译文文档，写入 `<书库根>/文章翻译/`，并维护 `index.json` 的「文章翻译」数组。

**一句话**：模型只写译文正文，其余（frontmatter/命名/索引）全由脚本 `scripts/translate-doc.mjs` 保证。

## 第零步：定位（先查事实）

1. **书库根**：`--book <书库根>`（集中模型 `$DSH_HOME/books/<projectKey(项目根绝对路径)>/`，桶名算法与 DSH format.ts 一致，无 `<项目名>-book` 中间层；宿主给的值优先，**传了就用它**；未传则脚本自动推导新桶，推荐传 `--root <项目根绝对路径>`）。
2. **源码路径键**：`工作区名 + '/' + 相对工作区根的路径`。这是 `--key` 的值，也是 frontmatter「源码路径」与 index.json「文章翻译」的键。
3. 产物命名由脚本自动算（与 file-doc 同规则：完整相对路径前缀），模型不手算。
4. **单篇不批量**：一次只翻译宿主指定的这一篇 md，绝不批量为其它文件翻译。
5. **范围**：只翻译项目文件内的 md 文档（宿主已校验：md/markdown 且不在书库内）；`.book/` 内的解读文档不翻译。

## 第一步：读原文档

1. 通读全文（Markdown 正文与 frontmatter 都要看；frontmatter 属文档元数据，可在译文正文前的「原文元数据」小节说明，不翻译）。
2. 梳理结构：标题层级、列表、表格、链接、代码块、引用块——翻译后结构逐一对应，不增删段落。

## 第二步：翻译（模型主干）

忠实原文翻译为简体中文，要求：

1. **符合原文**：不增删内容，不改义；段落、标题、列表、表格、引用、链接结构一一对应。
2. **特殊名词首次出现**：专有名词、技术术语、产品名、API/命令/包名等保留原文（英文），就地写 `原文（中文解释）`（原文后跟一对中文圆括号给解释），如 `CRLF（回车换行）`、`WebSocket（全双工通信协议）`；同篇再次出现直接用原文，不重复解释。
3. 普通英文词按含义翻译；**不要**给变量名/局部标识符/普通英文词加（中文）括号。
4. 代码块、行内代码、文件路径、URL 保留原文不翻译；代码块内的注释按术语规则处理（可翻译注释文字，代码本身不变）。
5. 全文简体中文；标题、frontmatter 的键名不翻译。

## 第三步：生成（gen）

脚本：`node scripts/translate-doc.mjs gen <源文件绝对路径> --book <书库根> --key <源码路径键> [--root <项目根绝对路径>] [--name <文档名>] [--content <译文正文>]`（未传 `--book` 时脚本自动 = `$DSH_HOME/books/<projectKey(项目根)>/`）

脚本自动完成：frontmatter（源码路径/层级: 文章翻译/生成时间）、文档命名（computeName 同 file-doc）、写入 `<书库根>/文章翻译/<名>.md`、index.json「文章翻译」upsert（保留其它数组；「项目根」字段写项目根绝对路径）。用 `--content` 传入已写好的译文正文，**模型不要手写 frontmatter**（脚本会前置拼接并剥掉正文里自带的旧头；「生成时间」= 本次翻译时刻，重译即刷新）。

## 第四步：汇报

1. 文档写完即落盘。
2. 汇报：源文档、译文文档路径、索引更新情况。

## 第五步：问题记录（自检）

先做实质判断——**这轮是否顺利，有没有值得沉淀给技能的坑**（不顺利就见招拆招后记下）。常见如脚本报错、参数不生效、返工、产出不符预期、路径失效、判断失误等，但**不限于此**——只要是这轮暴露出的、下次可能再踩的，就按 `plugins/dsh-plugin-file-system-zc/issues/_template.md` 记一条到 `issues/<date>-<序号>-<slug>.md` 并更新 `issues/README.md` 索引表。**顺利则跳过，保持零噪声**。

## 注意

- 同名译文直接覆盖（同一篇 md 重复翻译）；全简体中文。
- 脚本随本技能目录分发（`scripts/translate-doc.mjs`），可随包迁移。
- 与 folder-doc/file-doc/source-doc 分工：解读技能生成「目录概览/文件摘要/源码注解」，本技能只做「文章翻译」；命名同规则、分放不同子目录，不冲突。
