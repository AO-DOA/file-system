# 骨架批量填注解时把「块注释的注解行」与其后首个代码单元的注解行错位

> **2026-09-09 主线修复**：`src/host/abilities/source-doc/prompt.md` 骨架说明段补一条——
> 注解行紧跟该单元**最后一个** `代码: ` 行之后、位置随块内行数变化，禁止用「`@块` 行号 + 1」推算，
> 要求按 read 到的真实行号定位或直接以 `注解: ` 空位行作锚点。

## 场景（怎么触发）
L3 源码层注解、首次模式；骨架 443 行、136 个注解单元，按「每批 ≤20 单元」分 7 批，每批用 run_code 读骨架后按行号区间一次 edit 填充。出问题的是批 2（行 81–138 区段）。

## 现象（看到了什么）
批 2 返回 "cells: 19" 而非预期的 20；核对后发现 `@块 [55-55]` 的注解行 132 仍为空，而 135（`function ensureBookDir() {` 的注解行）被填成块注释的释义、138（return 语句的注解行）被填成函数声明的释义。原文形如：

```
130|@块 [55-55]（注释块，合并为一条注解）
131|代码:   // 当前工作区根的桶（加载/切换工作区时调用：打开过的根即注册为已知项目根）。
132|注解: 
133|@行 [56]
134|代码:   function ensureBookDir() {
135|注解: 
```

## 根因（为什么会这样）
我按「@块 行 + 1」推算注解行号，把 `@块 [55-55]` 的注解行误记为 135（实际是 132，块内裸源码行 131 之后才紧接注解行）；注释块与其后代码单元的注解行号彼此紧邻，凭肉眼推算易错位。批 2 的 fill 字典因此少了一个键（19 个）却没报错——edit 只替换字典中出现的行号，静默少填。

## 改法 / 临时绕过
对 132–138 区段单独重读原文，用一次 edit 把 132 补上块注释释义、135 改为函数声明释义、138 改为 return 释义，三处对齐；后续批次改为「先 read 该区段、再按 read 到的行号填」，不再凭推算。

## 复验（如何确认已解决）
验收程序统计：136 个注解行中空注解 0 个、无中文释义 0 个；135 个 `@行/@块` 单元与 135 个 `代码:` 行数量一致；抽查 132/135/138 三行内容与所在单元代码一一对应。
