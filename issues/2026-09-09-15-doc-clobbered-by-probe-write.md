# 产物 DOC 被一次试探性 write 清空，需整篇重写恢复

## 场景（怎么触发）
L2 文档已整篇写入 DOC（3496 字节）并通过读回检查，仅剩一处 `<桶名>` 尖括号需清理。为取用 edit 工具，我在程序里写了一句 `const e = await tools.write` 之类的探路代码，顺手跟了一句 `tools["write"]({ file_path: DOC, content: "" })`，本意是「占位/空操作」，实际执行了真正的写盘。

## 现象（看到了什么）
DOC 被覆盖为空文件（`update ... bytes: 0` 语义），刚写好的整篇文档被冲掉；必须重新组装全文再写一次。所幸工具返回了 `operation: update`，让我立刻发现写入真的发生了，未带着空产物收尾。

## 根因（为什么会这样）
把 `tools.write` 当成「可取用后不使用」的引用写进代码，忽略了 SDK 绑定里每个 `tools.X(...)` 调用即真实副作用；且清空内容用空字符串代替「跳过」，等于主动执行一次覆盖写。本质是缺少「试探代码不触碰写工具」的自我约束。

## 改法 / 临时绕过
立即用同一份完整正文（含 `<桶名>` 改为「桶目录」的修正）重新写入 DOC，读回确认 62 行、frontmatter 三行与章节标题齐备、无尖括号占位。后续不再在程序里写任何非必要的写工具调用。

## 复验（如何确认已解决）
读回 DOC 全文：总行数 62、`源码路径/层级/生成时间` 三行逐字一致、四个章节标题与导出表头命中为 true、`/<[^>\n]*>/` 正则结果为 false。核验通过。

2026-09-10 宿主加固：L1/L2 `verify` 增加「产物非空」校验（`src/host/abilities/{file-doc,folder-doc}/index.js`）——子 agent 把 DOC 清空成 0 字节时占位残留校验会漏过（空串不含占位符），非空校验直接置 error；新增测试覆盖（`tests/gen-scope.test.js` L1/L2 空产物 → error）。此为防御兜底，正常流程不触发。
