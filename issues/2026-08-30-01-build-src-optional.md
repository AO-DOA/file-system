# build 曾强制要求 `--src`（真实读源码路径），跨项目时不便捷且多读一次源文件

> 这是把"问题记录"机制落地后记的第一条。`recurrence: 2` 表示此前已反复遇到类似"该把确定性工作交给脚本、模型却被迫承担"的问题。

## 场景（怎么触发）

执行 `build` 时旧写法是强制 `--src <真实源码路径>` + `--rel <写入文档的源码路径>` 配对。当目标项目不在当前工作区、或模型已把每行代码写进了骨架时，仍要额外指定一份真实源码路径，既繁琐又多读一次源文件。

## 现象（看到了什么）

- 模型必须理解 `--src`（真实读路径）与 `--rel`（写入 frontmatter/index 的路径）的区别，跨项目时容易配错。
- 骨架里其实已含每行代码原文（`代码: xxx`），build 却还要再读一次 `--src`，存在信息重复。

## 根因（为什么会这样）

历史上 build 的权威行号参数设计成"必须显式给真实源码路径"，是假设骨架不可信、需重读源码校准。但骨架由脚本自身生成、SKILL.md 也明确约定"模型不得改行号/代码行"，因此骨架内代码即是权威——`--src` 不再是必需。

## 改法 / 临时绕过

本轮将 `build` 的 `--src` 改为**可选**：缺省时用骨架内已含的 code 原文（`parseSkeleton` 增加状态机读取 `代码:` 到 `注解:` 之间的代码），只有跨项目/需行号权威复验时才传 `--src`。同时新增 `--doc-name`（同名消歧）与 `layout` 子命令（推导书库根），减少模型手工算路径。

## 复验（如何确认已解决）

用真实源码 `src/client/index.js`（513 个可注解单元）端到端跑 `build`（**不传 `--src`**），成功产出 32KB 文档、术语表与行号正确；另测 `--src` 权威模式不回归。状态置 `已验证关闭`。
