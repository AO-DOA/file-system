# build 产物排版乱（行上方注解与代码错位、单元被空行割裂），且脚本缺少排版防错

> 标题概括本次踩坑；[2026-08-30-02](2026-08-30-02-extractterms-falseterms.md) 关联的术语污染本次一并强过滤。

## 场景（怎么触发）

`node scripts/source-annotate.mjs build 骨架.md --src 源.go --rel proj/源.go --pkg proj --book <书库根>` 生成成品后，打开 `源码注解/<pkg>-<file>.md` 发现排版很乱。

## 现象（看到了什么）

产物正文（`reasonix-diff.md` 实测，重命名 `// [7]` 那一段）：

```go
import (  // [3] 开始导入（import）这段需要的依赖包。

	"context"  // [4] 导入 context（上下文）包，用于超时与取消控制。
                                    ← 单元间盲插空行，本应连续的 import 组被割裂
	"fmt"  // [5] ...

// [7] 导入 os/exec（命令行执行）包，用于运行外部命令如 git/go。  ← 顶格，注解与下面缩进代码左右错位
	"os/exec"
```

另外 `ctx`、`base`、`a`、`m` 等**局部变量名/惯用缩写**被误收进术语表（术语污染），要人工 step 返工剔除。

## 根因（为什么会这样）

`build` 渲染段（`codeOut` 组装）有三个漏洞：

1. **行上方注解不带缩进**：`codeOut.push(`// ${rangeLabel} ${note}`)` 直接顶格输出，而它注解的代码行带 Tab 缩进，注解与代码左右错位——这是"乱"的最大来源。
2. **每个可注解单元后盲插一个空行**：`codeOut.push('')` 把本来连续的 `import` 组、struct 字段、连续语句割裂成碎片。
3. **脚本只校验"行号越界/单元非空"，从不校验"排版是否合理"**：所以上述乱排版能毫无阻挡地落盘。
4. **`extractTerms` 的黑名单不含局部变量/惯用缩写**：`ctx/err/i/m/base` 等命中 `camelCase` 候选正则，又不在 `NOT_A_TERM_ID` 里，于是被误收进术语表。

## 改法 / 临时绕过

已在 `source-annotate.mjs` 落地：

- **排版修复**（渲染段）：
  - 行上方注解继承其代码行的前导缩进（`${indent}// ${rangeLabel} ${note}`）；
  - 空行按源码行号连续性判断：`r.start - prevEnd > 1`（源码本有空行/被跳过行）才插一个空行，相邻（`==1`）不插空行。
- **防错闸门**（新增 `checkHealth(codeOut)`，在 `build` 落盘前调用，异常直接 `process.exit(1)`）：
  - 注解占比 < 50% → 报"疑似大量代码行未填注解"；
  - 行上方注解缩进 ≠ 其后目标代码行缩进 → 报"装修行与代码缩进不一致"；
  - 正文出现连续 2+ 空行 → 报"被空行割裂"；
  - 找不到任何 `// [N]` 注解标记 → 报"疑似全部漏注解"。
- **术语污染过滤**（`extractTerms` 新增 `POLLUTED_ID` 正则）：`ctx/err/e/r/ok/ret/res/tmp/val/out/base/args/n/i/j/k/...` 等局部变量/惯用缩写一律不进术语表（正文仍保留原词，只去术语表）。

## 复验（如何确认已解决）

- 重跑正常骨架+build：产物中 `import (...` 组内代码紧密相邻（不再空行割裂）、行上方注解缩进与代码一致。
- 漏填注解（只给 1 条）→ build 应 fail-fast 报"注解占比过低"，exit=1，不产出裸代码页。
- 注解含 `ctx（中文）` → 术语表里不再出现 `ctx`，但正文 `// [N] ... ctx（中文）` 保留。
- `node --check` 通过；两处脚本副本（工作区 `plugins/...` 与 `~/.agents/...`）一致。

## 复验结果（2026-09-03 实际跑证，全部通过）

- ✓ 正常骨架 build（Go import 组场景）：`[3]`–`[7]` 连续单元紧密相邻无空行割裂；行上方注解 `// [4]` 以 Tab 缩进、与目标代码行一致；源码本有空行处（1→3、7→9）各正确保留一个空行。
- ✓ 10 个单元全部留空 → `checkHealth` fail-fast，EXIT=1，报「注解占比过低（0%<50%）」「找不到任何 `// [N]` 注解标记」，不落盘。
- ✓ 产物无「术语表」章节（集中术语表已移除）；`ctx` 等变量名就地保留原文、不加（中文），翻译只挂在真正术语后（context（上下文）等）。
- ✓ `node --check` 通过；`~/.agents` 下的脚本副本已不存在，无双副本同步问题。
