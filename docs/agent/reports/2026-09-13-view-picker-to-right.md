# 视图选择器搬进右列：实测报告（2026-09-13）

**任务**：按用户裁决把顶栏的视图选择胶囊从 `.fs-hbar-mid` 移到 `.fs-hbar-right`，右列次序为
**视图选择 → 解读选择 → 编辑⇄保存 → 分栏**，中列只剩路径。只搬位置，不新增元素、不改交互语义。

**结论一句话**：搬位置本身干净（跨列 0 档、同列 0 档、顶栏高恒 `{48}` 全守住，交互与元素一字未动），
但右列 min-content 多出约 74px ⇒ **右列被整块裁的下界由 307 抬到 389，破门禁（≤360）**；
收纳策略四条候选已逐条实测，源码只落「纯搬位置」版，等主代理/用户裁决。

## 4. 单档取证（面板 389，`/tmp/dsh-ui-probe/out-lian-dump389.json`）

`S2-trlong` @389 的列盒与逐元素矩形：

```
列盒  left [14,140]   mid [150,150]（宽 0）   right [160,375]
hbar  [14,375]
L 工作区按钮 14–58（工作区名已隐藏，wsLabShown=false）  折叠 66–102  刷新 104–140
M 路径 150–150 ⇒ vis 全零（被压到 0，整块不可见 —— 门禁第 3 项里属于 M 列）
R 视图「文章翻译」160–228（68px）  解读「重新翻译」234–270  未保存 276–318.7
  编辑/保存 324.7–368.7  分栏 raw 374.7–410.7 而 vis 374.7–375 ⇒ 只剩 0.3px 宽（计为部分裁切）
```

**成因**：容器宽 361px（面板 389 − `.fs-wrap` 左右内边距 28），而此时

- 左列已收到最小 **126px**（工作区名早被第二档 `@container (max-width:550px)` 隐藏）；
- 中列被 `minmax(0,1fr)` 压到 **0**（列盒 `[150,150]`）；
- 右列要放 68 + 36 + 42.7 + 44 + 36 + 4×6 = **250.7px**。

126 + 10 + 0 + 10 + 250.7 = 396.7 > 361 ⇒ 溢出 35.7px，正好把最后一项（分栏）几乎整块推出容器。
**所以这不是「中列/路径占地方」的问题，而是左列与右列的 min-content 之和超过了容器**：
中列可压缩到 0、路径让位不能救。

抬升量对账：下界 307 → 389 = **+82px**；新增需求是「胶囊 68px + 右列一处 6px gap」= **74px**，
余下 8px 差异**未定位**（未逐元素反算基线 307 档的右列各元素宽度）。

## 7. 为什么只有「收纳」能过线（机制分析）

顶栏是 `grid-template-columns:auto minmax(0,1fr) auto`，溢出条件是
`左列 min-content + 20px(两处列 gap) + 中列 + 右列 min-content > 容器宽`。

- **中列已无路可让**：它是 `minmax(0,1fr)`，在 389 档实测列宽已经是 **0**；路径 `.fs-hd-path` 自带
  `overflow:hidden;text-overflow:ellipsis`，所以「藏掉路径」不省任何 min-content（§4 的列盒已证）。
- **左列已收到最小**：工作区名在面板 ≤578 时就被第二档隐藏，389 档实测 `wsLabShown=false`、
  工作区按钮宽 44px（纯图标）。**所以「把第二档阈值往上提」对 389 附近毫无帮助** —— 那里早就收完了。
- **只剩右列 min-content 可减**，而右列每一项都是功能键（视图选择 / 解读选择 / 编辑⇄保存 / 分栏）
  或状态标记（未保存）。**没有「免费的像素」**：不过线就必须拿掉其中一项的可见性。

同理，`flex-wrap` 折行被既有裁决明确禁止（会让顶栏高度不再恒为 48px），减小 `.fs-wrap` 内边距或右列
gap 只能省 8–28px（仍到不了 389 → 360 的 29px 缺口，且要动全局观感），都未作为候选。
