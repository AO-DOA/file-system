证据一律指向 `docs/agent/reports/` 下的归档报告章节（报告是逐字归档的一手证据）。

## A. 已验证的负结果（别再试）

### A-1 给 `.fs-hbar-left > span` 加 `min-width:0`，对列宽分配**毫无改善**
- **现象**：左列工作区按钮所在的 `Menu` root `<span>`（`inline-flex`）把左列顶到 284.8px，中列被
  `minmax(0,1fr)` 让到 0，右列被挤出容器后由 `.fs-hbar{overflow:hidden}` 整块裁掉。
- **结论**：加 `min-width:0` 后 3306 档判据与现实现**逐档相同**。原因：`min-width` 只改**压缩下限**，
  不改 **min-content contribution**；列宽分配看的是后者，而后者由内容决定（受 `.fs-wsbtn{max-width:220px}` 钳制）。
- **证据**：`reports/2026-09-11-ui-revamp-stage2.md` §5「#8 的根因」两条负结果。
- **重试**：**否**。真正的杠杆是阈值/收纳（见 A-3），不是 `min-width`。

### A-2 同一处的第二条负结果：只折行、不给该 span `min-width:0`
- **现象**：S0/S1/S3 在面板 200–276 仍被裁（左块整行内容超宽）。
- **证据**：同上（stage2 §5 第二条）。
- **重试**：**否**。

### A-3 「极窄时三块各占一行」的折行方案 —— 已被否
- **现象**：加上折行两规则后 200→1200 全部 3306 档「被裁 0 / 跨列 0」，但同列重叠仍有 21 档
  （面板 200–206，相交 107px²），且面板 ≤700 时**顶栏高度 ×3**。
- **结论**：用户裁决「逐级收纳、保持单行」，折行方案不落地。顶栏单行是硬门禁（高度集合恒 `{48}`）。
- **证据**：`reports/2026-09-11-ui-revamp-stage2.md` §6；`reports/2026-09-11-ui-revamp-stage3b.md` §0。
- **重试**：**否**（除非上游明确撤销「保持单行」这条裁决）。

### A-4 两个档的阈值**不能留缝**
- **现象**：把折行阈值压到 380（其余同折行方案）⇒ 面板 409–441（S1）/ 409–459（S2）**重新出现右列被裁**；
  把工作区名阈值取 428（hbar）⇒ 缝里的面板 457/458/459 重新出现右列被裁。
- **结论**：图标化档与折行档（后来是「图标化档与工作区名档」）**必须是同一个阈值**。缝里那段没有任何
  规则生效，于是回到基线的最坏状态。判据：`N ≥ 460 − 28 = 432`（hbar），否则留缝。
- **证据**：`reports/2026-09-11-ui-revamp-stage2.md` §6；`reports/2026-09-11-ui-revamp-stage3a.md` §1 表格
  与 §3（留缝反证的数据文件 `/tmp/stage3/out-n428.json`，**该数据文件未随报告归档**——见 §C-1）。
- **重试**：**否**。新档阈值一律做「与相邻档无缝相接」的验算，再逐档实扫确认。

## B. 判据与阈值口径

### B-1 分档动作只用 `@container`，不用「测溢出再打标记」
- **现象**：`@container` 随容器宽度**单调**变化；而「测溢出再打 `data-*` 标记」会因图标化让内容变窄
  而反复撤销标记（**滞回振荡**）：内容窄了→不溢出→撤标记→文字回来→又溢出。
- **结论**：阈值唯一真相源在**样式表**，JS 不持像素阈值。宿主有 11 处 `@container` 先例。
  旧设想的 `--fs-hbar-w` JS 通道已在第三段 a 删除（`grep -rn "fs-hbar-w\|useHbarWidth" src tests`
  **exit 1、0 命中**，第三段 b 复跑确认）。
- **证据**：`reports/2026-09-11-ui-revamp-stage2.md` §1 第 8 行；`reports/2026-09-11-ui-revamp-stage3b.md` §4.1 第 3 行。
- **重试**：**否**（改回测量打标记＝把振荡请回来）。

### B-2 阈值按约 **8% 余量**取整；绝对像素端点会漂
- **现象**：绝对像素端点随**字体渲染**浮动，同一份 CSS 换字体族就会移动。
- **结论**：阈值 = 实测临界 hbar × 1.08 再取整。三处同口径：`432 × 1.08 ≈ 466 ⇒ 470`；
  `672`（相对最坏文字态下界 651 留 49px = **7.9%**）；`760`（窗口上界面板 720 ⇒ 下界 hbar 692，按 8% 取整）。
- **例外**：第三段 b 的右列下界 356 距门禁上限 360 **只剩 4px（约 1.1%）**——这是 R4 分屏按钮给右列
  +42px min-content 的结果，属登记在案的残留（`PROGRESS.md` §5 #11），不是可接受的常态。
- **证据**：`reports/2026-09-11-ui-revamp-stage2.md` §2；`stage3a.md` §3；`stage3b.md` §3.4 与 §7。
- **重试**：换字体族 / 换浏览器**必须复测**三个切换点（578/579、788/789 与首个右列裁切档）。

### B-3 门禁只认四项指标，「部分裁切」不进任何门禁
- **现象**：第三段 a 末态在面板 499–534 有 17–36 档「右列部分裁切」（看得见、点得到、显示不全），
  但四项门禁在这些档上全是 0。
- **结论**：四项 = 跨列可见重叠 / 同列可见重叠 / 被整块裁掉 / 右列被整块裁；「部分裁切」（`partRightN`）
  是**另一项指标**，只作回归信号。口径正文见 `tools/ui-probe/README.md` §1.3。
- **证据**：`reports/2026-09-11-ui-revamp-stage3b.md` §0 与 §7 第 7 条（S0 在面板 200–209 的 10 档部分裁切）。
- **重试**：不要把部分裁切混进门禁（会得到一套无法通过的门槛），但要盯着它别从 0 变回非 0。

### B-4 指标口径必须连同**统计集合**与**产出它的 flags** 一起写清
- **现象（两个真实形态，同日发生）**：
  ① **flags 不一致被误读成口径变化**：`/tmp` 里一份产物记 `gone 1010`，另一份记 `gone 2013`
  （`goneRight 754 → 1757`），于是得出「`--menus` 改变了汇总表计数口径」。实测两跑才知道：
  2013 那份（`out-fix-cur.json`）的 `wsLabShown` 恒为 `null` ⇒ 它**漏了 `--wsicon`**；补上该 flag 后
  `--menus` 的两份产物与基线**逐档逐字段 0 差异**（3857 档）。真正的口径差异在 `--wsicon`，
  与 `--menus` 无关。
  ② **统计集合会静默变化**：四项门禁只统计「三列内的 `button` + `.fs-hd-path` + `.fs-dirty`」。
  探针复刻的菜单面板用 `div.mr-list` / `div.mr-item`，产不出候选，所以打开态的读数不变；
  而真实 `Menu` 的行是 `<button role="menuitem">` —— 一旦把复刻行也改成真 `button`，
  面板自身就落进「被裁」计数，**同一份源码的读数会突然翻倍，而那不是回归**。
- **结论**：一个数字要能复现，必须同时交出三样：**(a) 判据**（怎么算的）、**(b) 统计集合**
  （哪些元素进计数）、**(c) 产出它的 flags 组合**。缺 (b)/(c) 的数字在换一次调用条件后就不再可比，
  而错误会以「回归」的样子出现。口径变了旧结论作废，**统计集合或 flags 变了同样作废**。
- **证据**：`tools/ui-probe/README.md` §1.2（统计集合）、§1.5、§1.6（flags 对照表：1010/754 vs
  2013/1757，判别特征 `wsLabShown=null`）；实测产物 `/tmp/e-probe/out-e-{base,inline-view-inline,
  inline-all-inline}.json`（各 3857 档，前后脚同机三跑）与 `/tmp/menu-probe/out-fix-cur.json`
  vs `out-fix-cur-ws.json`（**都不进仓库**，两行命令可复跑）。
- **重试**：不适用；这是引用数字前的固定动作（与 C-1「数字必须来自可复跑的产物文件」同一条线，
  这里补上「同一个文件 + 不同 flags 也等于两个口径」）。

### B-5 primitives 的 `Tooltip` **不能**挂在 primitives 的 `Button` 上（React 18 无 ref）
- **现象**：想用官方 `Tooltip` 替掉顶栏的原生 `title`，写成 `<Tooltip><Button/></Tooltip>` 时气泡
  **永不渲染**，控制台同时报 `Function components cannot be given refs`。
- **结论**：`Tooltip` 靠 `cloneElement(children, {ref})` 取锚点，而本包 `Button` 是**普通函数组件**
  （无 `forwardRef`，`0.1.5-rc.1` 与 harness 源码一致），React 18 下 `ref` 挂不上 ⇒ `anchor.current`
  恒 null。**锚点必须是原生元素**：外面加一层 `.fs-tipwrap` span（与 `Menu` 自己的 `.mr` root 同做法，
  只做收缩包裹）。宿主 4 处 `Tooltip` 也一律包原生 `<button>`/`<span>`，从无包 `Button` 的先例。
- **证据**：报告 `reports/2026-09-12-collapse-split-edit-merge.md` §D（装置 `/tmp/d-tooltip-ref.mjs`：
  最小复刻真实 `Tooltip` 的 ref 机制 + 正对照，`Button` 组「气泡不渲染 + ref 警告」、
  `<span>` 组「气泡渲染」）；`Button.tsx` 与 `lib/index.js:1565` 的实现；宿主 4 处调用点。
- **重试**：**否**。别去「顺手去掉那层 span」求简洁 —— 去掉就等于气泡消失（回归即此）。

### B-6 加一层包装 span 的几何代价要**实测**，别推断「反正它是 inline-flex」
- **现象**：为挂 `Tooltip` 给 5 个顶栏按钮各加一层 `.fs-tipwrap`（`display:inline-flex`）。单看是
  「收缩包裹、与裸按钮等价」，但顶栏是 `@container` 分档 + `minmax(0,1fr)` 分配 + `overflow:hidden`
  的网格，min-content 贡献稍有变化就会体现在窄档的裁切上。
- **结论**：实测**逐档逐字段 0 差异**（3857 档 × 全部字段，`--wsicon`）⇒ 这一层是几何中性的。
  方法：拿探针产出的**自包含** HTML，只改 `const SCEN = [...]` 里的场景 DOM，再用**同一段页面内
  测量脚本**重跑并逐档 diff —— 只改 DOM、不改判据，两份读数才可比。
- **证据**：报告 §D 的 A/B/C 三变体对照（基线 / +锚点层 / +锚点层+合并按钮）；产物
  `/tmp/e2/out-{new-base,dom-d-wrapped,dom-bc-wrapped-merged}.json`（各 3857 档，**不进仓库**）。
- **重试**：不适用；「加一层 DOM」这类改动一律按此法先量再落。

### B-7 交互姿态的改动会让字典键**失去消费者**，但「删键」要单独裁决
- **现象**：B 段把「编辑/保存」合并成一个按钮 ⇒ `ZH.btnView`（「查看」）在 `src/` 里再无引用；
  D 段把两个「悬停即开下拉」的锚点排除在气泡之外 ⇒ `ZH.a11yViewPick` 也不再被消费。
- **结论**：本段**保留**两个键。理由：① 字典的既定角色是**产品文案注册表**（117 键里本就有只能由
  直连 API / 失败路径触发的串），「今天没有 UI 路径渲染它」不是成员判据；② 删键必须手改
  `tests/locale.spec.ts` 的三重硬断言（键序 + `toHaveLength` + 全等表），而那张表存在的意义正是
  让字典变动变成一次**刻意的、被复审的**动作 —— 为省一个条目去重写它不划算；③ 两个键描述的是
  **本段刚裁决掉的交互**（B 的合并、D 的悬停豁免），裁决若回摆（加「放弃编辑」入口或给下拉锚点
  留 `delayMs` 气泡），键还在原处。**代价如实登记**：字典里会有一条不再被消费的键。
- **证据**：`grep -n btnView src/ tests/`；`src/shared/locale.ts:40`；`PROGRESS.md` §5 #12 的
  「可访问名缺口」清单；本段报告 §B/§E 的判断段。
- **重试**：不适用；判别方法是「**产品是否真的去掉了这个交互**」——去掉（如独立的「查看」按钮）
  才是删键的候选，仅因**设计选择**暂时不用（如气泡豁免）先留。

## C. 流程与协作

### C-1 数字必须来自**可复跑的产物文件**，转述前核对
- **现象**：主代理转述子代理数字时出过三次错：口径 A/B 混淆、把「231 档 / 797 对」拆错、
  基线「0 / 281」实为「6 / 281」。
- **结论**：报告与台账里的每个数字都要写清「从哪个产物文件、哪一档读出来的」。转述 = 高风险动作，
  必须回原文核对。
- **证据与一处诚实说明**：上述三个错值**只在对话上下文里出现过**——对四份归档报告全文 grep
  `231` / `797` / `281` **0 命中**，所以本轮**无法从归档证据复核它们**。这本身就是教训：
  **转述产生的错误没有留痕，因此无法审计**。反过来，探针的 JSON（每份约 1MB）是可复跑产物，
  但它不进仓库、旧的已在 `/tmp` 里失掉（见 A-4 的证据栏）。
- **重试**：不适用；这条是纪律。

### C-2 并行跑覆盖率必须隔离 `reportsDirectory`
- **现象**：共用 `coverage/.tmp` 时生成崩溃（实测 4 次跑崩 3 次），表现为 `ENOENT ... coverage/.tmp`。
- **结论**：并行/多次跑覆盖率一律
  `npx vitest run --coverage --coverage.reportsDirectory=/tmp/<唯一目录>`，
  再把同一目录用 `--reports-dir` 指给 `node scripts/verify-coverage-scope.mjs`（它默认读
  `coverage/coverage-summary.json`）。`scripts/verify-stage.mjs` 已按这个方式实现。
- **陷阱**：`npm run test:coverage -- --coverage.reportsDirectory=…` **不能用**。
  npm 把附加参数追加到脚本字符串**末尾**，即落到 `…; if [ $cov -ne 0 ] || [ $scope -ne 0 ]; then exit 1; fi`
  **之后**，直接破坏 shell 语法。要用就绕开 npm script，走 `npx vitest run …`。
- **证据**：`PROGRESS.md` §2「注意事项」第三条；
  `scripts/verify-coverage-scope.mjs` 的失败文案里也复述了同一坑。

### C-3 派单书是人写的、会错 —— 先核前提再干活
- **现象**：四段改造里，**三份**报告开头都有「你给的前提里，N 处需要订正」一节（N = 1 / 3 / 3）。
  本轮又添一例：S6 的「超长工作区名」派单书写 **79 字符**，实测 `String.length === 89`（差 10，
  与报告里的 79 一致，说明错值从报告抄进了派单书）。
- **结论**：开工第一步是把任务书里的事实性断言逐条复现一遍，错了在报告开头写明订正，
  再按订正后的做。别一边怀疑一边照做。
- **证据**：`reports/2026-09-11-ui-revamp-stage3a.md` §1；`stage3b.md` §1；
  `tools/ui-probe/README.md` §3（S6 长度按实测记）。
- **重试**：不适用；这条是固定动作。

### C-4 写「怎么得到」比写「是多少」耐用
- **现象**：台账与注释里的绝对数字会随代码改动漂移，漂移后没人知道哪个还是真的。
- **结论**：记「怎么测出来」+「当时的实测值」+「口径」，别只记一个孤零零的数。口径变了，旧数就该作废。
- **证据**：`PROGRESS.md` §3「注释与台账里的数字会漂移」一节。

## D. 探针与读数

### D-1 `--window-size` 不够大、或格式写错 ⇒ hit-test **假红**
- **现象**：窗口比元素窄时元素落到视口外，`elementFromPoint` 拿不到命中（`hitTag=NULL`），
  探针把它判成「不可点」。**格式坑**：Chrome 的 `--window-size` **只认 `W,H`**，写成 `1600x1000`
  会被**静默忽略**并退回默认窗口。
- **结论**：`--window` 要比最宽采样档（默认 1200）大出余量，默认 `1600,1000` 即照此取；调高
  `--sn/--sw` 或加宽采样区间时必须同步调窗口。判别口诀：**只有 `unclickN` 一项集体变红、而矩形 /
  重叠 / 裁切 / 顶栏高度全正常时，先怀疑窗口尺寸**（后四类读数不看视口）。
- **证据**：`tools/ui-probe/README.md` §2.2 第 2 条。实测：本轮把格式误写成 `WxH` 时，面板 830–1200
  档全体误报不可点（260 处字段差异）；改成 `W,H` 后与 `/tmp` 原版逐档逐字段 **0 差异**。
- **重试**：不适用；这是跑探针的固定前置条件。

### D-4 探针读数**跨运行**有可测的非确定性 —— 别拿 1–2 档差异当回归
- **现象**：同一份 CSS、同一个脚本、同一台机器，两次运行之间也会有个位数的档对不上。实测标定
  （`--wsicon` 全扫 3857 档 × 14 字段）：`/tmp` 原版脚本「历史那次 vs 现在这次」有 **60 处**字段差异
  （`genLabShown` 48，`goneN` / `goneMidN` / `partRightN` 各 4），全部落在档界附近。
- **结论**：判回归看**结构性指标**——「0 档」「下界」「顶栏高集合」；不要拿单次运行里 1–2 档的差异
  当回归。要坐实某个差异，同条件复跑两次再下结论。
- **证据**：`tools/ui-probe/README.md` §4；本轮三方比对（仓库版 vs 原版本次复跑 = 0 差异；
  原版历史 vs 原版本次 = 60 处）。
- **重试**：不适用；这是读数的解读纪律。

### D-2 位置参数被**静默忽略**
- **现象**：参数解析只认 `--名` / `--名=值`，别的字符串直接丢掉且不报错。`node … probe.js now`
  会用默认 `--tag=probe` 覆盖上一轮产物，让人误以为「跑了新变体、结果没变」。
- **结论**：跑变体必须写 `--tag=`，并回看 stdout 里打印的 JSON 路径确认 tag。
- **证据**：`tools/ui-probe/README.md` §2.2 第 1 条。
- **重试**：不适用。

### D-3 探针量的是**工作树现状**，不是运行中的产物
- **现象**：CSS 从 `src/client/index.tsx` 的 `const CSS = [...]` 逐字解析——不 build 也能量到新样式；
  反过来**看不到** `client/client.js` 里的旧样式。
- **结论**：改完 CSS 立刻能量，这是它快的原因；要对照「运行中是什么样」，得用 `--css=<历史快照>`
  指过去（例：`/tmp/stage3/stage2-end.tsx`）。
- **证据**：`tools/ui-probe/README.md` §4。
- **重试**：不适用。

### D-5 探针只覆盖它**构造过**的静态场景 —— 交互态缺陷会全绿溜过
- **现象**：3857 档四项指标**全绿**（跨列 0 / 同列 0 / 右列整块裁下界 357 / 顶栏高集合 `{48}`）的
  同时，页面上「悬停看不到下拉」—— 静态 DOM 里根本没有菜单面板，探针量不到它。
- **结论**：几何探针的绿只证明**它构造过的那些场景**没问题。凡属**交互态**的缺陷（浮层、开关、
  异步、悬停 / 焦点），**发现即固化**成探针的一个新场景 / 新形态，否则同类缺陷下一次仍会全绿。
- **证据**：`tools/ui-probe/README.md` §1.5（新选项 `--menus` 的口径）与 §4 第 1 条（用法纪律）；
  实测两组读数：`--menus=inline` 视图面板 **3306/3306 档整块不可见**、`--menus=portal` **0 档被裁**
  （产物 `/tmp/menu-merge/out-full-*.json`，不进仓库；两行命令可复跑）。
- **重试**：不适用；这是固定动作。

## E. 浮层与裁剪

### E-1 `overflow:hidden` 的兜底裁剪会连浮层一起吃 —— primitive 有 `portal` 就优先用它
- **现象**：`.fs-hbar` / `.fs-hbar-mid` 为消跨列重叠加了 `overflow:hidden`，同一个顶栏里的三个下拉
  （`.mr-list`，`position:absolute`）因此成了裁剪链内的后代，被**整块切掉**：视图选择器下拉在
  全部 3306 档里可见高恒 0，解读选择只剩 0–6px。
- **结论**：`overflow != visible` 的盒子就是**祖先裁剪盒**，任何绝对定位浮层（下拉 / 气泡 / 卡片）
  只要落在它的子树里就会被切。**消重叠与浮层不是二选一**：primitive 若带 `portal` 类选项
  （`Menu` 的 `portal`）就优先用它把面板挂到 `document.body`，裁剪声明**一个都不用撤**。
- **证据**：`lib/types/Menu.d.ts` 的原文注释「Use when an ancestor's overflow clipping would crop
  the in-place list」；`src/client/index.tsx` 三处 `Menu` 的 `portal` 与旁边那段注释；
  `PROGRESS.md` §3「顶栏三个下拉被 `overflow` 裁剪」；
  `reports/2026-09-11-ui-revamp-menu-clipping.md` §3 与 §5。
- **重试**：**否**。别为浮层撤裁剪（撤了跨列重叠立刻回来），也别自绘一套带 portal 的下拉。

### E-2 反证：`contain: layout`（含 `container-type:inline-size`）**不**裁 `fixed` 后代
- **现象**：曾推断 `.fs-hbar{container-type:inline-size}`（＝ `contain: layout style inline-size`）
  会让该盒成为 `fixed` 后代的包含块，从而影响浮层的定位与裁剪，并据此怀疑「就地渲染被裁」另有其因。
- **结论**：**实测否证**。同一个盒子里放 `position:fixed;left:100px;top:100px` 的子元素，其 rect 仍是
  **视口坐标**（没有相对盒子偏移），且 `overflow:hidden` **不裁**这个 fixed 子元素 —— 在**盒外**、
  子元素内取 `elementFromPoint` 能命中它；有无 `container-type` 的对照盒读数相同。所以就地面板被裁的
  唯一原因是**面板自己是 `absolute`**。推论：换 `position:fixed` 的浮层（如 primitives 的 `Tooltip`，
  `Tooltip.module.css` 第 1–3 行）不必担心被裁剪盒吃。
- **证据**：`reports/2026-09-11-ui-revamp-menu-clipping.md` §1 第 1 条（订正项，逐条给了两盒的 rect 与
  `elementFromPoint` 结果；原始装置 `/tmp/containment.html` 未归档，机器重启即失——结论已随报告入库）。
- **重试**：**否**。别再为「`container-type` 会不会改变 fixed 后代的坐标基准 / 裁剪」重做实验。
