# 经验卡（`docs/agent/lessons.md`）

一条一行到几行，每条写清：**现象 / 结论 / 证据在哪 / 还要不要重试**。
证据一律指向 `docs/agent/reports/` 下的归档报告章节（报告是逐字归档的一手证据）。
「重试」写「否」的，是**已经实测过、无效**的方案——别重来一遍。

## A. 已验证的负结果（别再试）

### A-1 给 `.fs-hbar-left > span` 加 `min-width:0`，对列宽分配**毫无改善**
- **现象**：左列工作区按钮所在的 `Menu` root `<span>`（`inline-flex`）把左列顶到 284.8px，中列被
  `minmax(0,1fr)` 让到 0，右列被挤出容器后由 `.fs-hbar{overflow:hidden}` 整块裁掉。
- **结论**：加 `min-width:0` 后 3306 档判据与现实现**逐档相同**。原因：`min-width` 只改**压缩下限**，
  不改 **min-content contribution**；列宽分配看的是后者，而后者由内容决定（受 `.fs-wsbtn{max-width:220px}` 钳制）。
- **证据**：`reports/2026-09-11-ui-revamp-stage2.md` §5「#8 的根因」两条负结果。
- **重试**：**否**。真正的杠杆是阈值/收纳（见 A-3），不是 `min-width`。

### A-2 同一处的第二条负结果：只折行、不给该 span `min-width:0`
- **现象**：S0/S1/S3 在面板 200–276 仍被裁（左块整行内容超宽）。
- **证据**：同上（stage2 §5 第二条）。
- **重试**：**否**。

### A-3 「极窄时三块各占一行」的折行方案 —— 已被否
- **现象**：加上折行两规则后 200→1200 全部 3306 档「被裁 0 / 跨列 0」，但同列重叠仍有 21 档
  （面板 200–206，相交 107px²），且面板 ≤700 时**顶栏高度 ×3**。
- **结论**：用户裁决「逐级收纳、保持单行」，折行方案不落地。顶栏单行是硬门禁（高度集合恒 `{48}`）。
- **证据**：`reports/2026-09-11-ui-revamp-stage2.md` §6；`reports/2026-09-11-ui-revamp-stage3b.md` §0。
- **重试**：**否**（除非上游明确撤销「保持单行」这条裁决）。

### A-4 两个档的阈值**不能留缝**
- **现象**：把折行阈值压到 380（其余同折行方案）⇒ 面板 409–441（S1）/ 409–459（S2）**重新出现右列被裁**；
  把工作区名阈值取 428（hbar）⇒ 缝里的面板 457/458/459 重新出现右列被裁。
- **结论**：图标化档与折行档（后来是「图标化档与工作区名档」）**必须是同一个阈值**。缝里那段没有任何
  规则生效，于是回到基线的最坏状态。判据：`N ≥ 460 − 28 = 432`（hbar），否则留缝。
- **证据**：`reports/2026-09-11-ui-revamp-stage2.md` §6；`reports/2026-09-11-ui-revamp-stage3a.md` §1 表格
  与 §3（留缝反证的数据文件 `/tmp/stage3/out-n428.json`，**该数据文件未随报告归档**——见 §C-1）。
- **重试**：**否**。新档阈值一律做「与相邻档无缝相接」的验算，再逐档实扫确认。

## B. 判据与阈值口径

### B-1 分档动作只用 `@container`，不用「测溢出再打标记」
- **现象**：`@container` 随容器宽度**单调**变化；而「测溢出再打 `data-*` 标记」会因图标化让内容变窄
  而反复撤销标记（**滞回振荡**）：内容窄了→不溢出→撤标记→文字回来→又溢出。
- **结论**：阈值唯一真相源在**样式表**，JS 不持像素阈值。宿主有 11 处 `@container` 先例。
  旧设想的 `--fs-hbar-w` JS 通道已在第三段 a 删除（`grep -rn "fs-hbar-w\|useHbarWidth" src tests`
  **exit 1、0 命中**，第三段 b 复跑确认）。
- **证据**：`reports/2026-09-11-ui-revamp-stage2.md` §1 第 8 行；`reports/2026-09-11-ui-revamp-stage3b.md` §4.1 第 3 行。
- **重试**：**否**（改回测量打标记＝把振荡请回来）。

### B-2 阈值按约 **8% 余量**取整；绝对像素端点会漂
- **现象**：绝对像素端点随**字体渲染**浮动，同一份 CSS 换字体族就会移动。
- **结论**：阈值 = 实测临界 hbar × 1.08 再取整。三处同口径：`432 × 1.08 ≈ 466 ⇒ 470`；
  `672`（相对最坏文字态下界 651 留 49px = **7.9%**）；`760`（窗口上界面板 720 ⇒ 下界 hbar 692，按 8% 取整）。
- **例外**：第三段 b 的右列下界 356 距门禁上限 360 **只剩 4px（约 1.1%）**——这是 R4 分屏按钮给右列
  +42px min-content 的结果，属登记在案的残留（`PROGRESS.md` §5 #11），不是可接受的常态。
- **证据**：`reports/2026-09-11-ui-revamp-stage2.md` §2；`stage3a.md` §3；`stage3b.md` §3.4 与 §7。
- **重试**：换字体族 / 换浏览器**必须复测**三个切换点（578/579、788/789 与首个右列裁切档）。

### B-3 门禁只认四项指标，「部分裁切」不进任何门禁
- **现象**：第三段 a 末态在面板 499–534 有 17–36 档「右列部分裁切」（看得见、点得到、显示不全），
  但四项门禁在这些档上全是 0。
- **结论**：四项 = 跨列可见重叠 / 同列可见重叠 / 被整块裁掉 / 右列被整块裁；「部分裁切」（`partRightN`）
  是**另一项指标**，只作回归信号。口径正文见 `tools/ui-probe/README.md` §1.3。
- **证据**：`reports/2026-09-11-ui-revamp-stage3b.md` §0 与 §7 第 7 条（S0 在面板 200–209 的 10 档部分裁切）。
- **重试**：不要把部分裁切混进门禁（会得到一套无法通过的门槛），但要盯着它别从 0 变回非 0。

## C. 流程与协作

### C-1 数字必须来自**可复跑的产物文件**，转述前核对
- **现象**：主代理转述子代理数字时出过三次错：口径 A/B 混淆、把「231 档 / 797 对」拆错、
  基线「0 / 281」实为「6 / 281」。
- **结论**：报告与台账里的每个数字都要写清「从哪个产物文件、哪一档读出来的」。转述 = 高风险动作，
  必须回原文核对。
- **证据与一处诚实说明**：上述三个错值**只在对话上下文里出现过**——对四份归档报告全文 grep
  `231` / `797` / `281` **0 命中**，所以本轮**无法从归档证据复核它们**。这本身就是教训：
  **转述产生的错误没有留痕，因此无法审计**。反过来，探针的 JSON（每份约 1MB）是可复跑产物，
  但它不进仓库、旧的已在 `/tmp` 里失掉（见 A-4 的证据栏）。
- **重试**：不适用；这条是纪律。

### C-2 并行跑覆盖率必须隔离 `reportsDirectory`
- **现象**：共用 `coverage/.tmp` 时生成崩溃（实测 4 次跑崩 3 次），表现为 `ENOENT ... coverage/.tmp`。
- **结论**：并行/多次跑覆盖率一律
  `npx vitest run --coverage --coverage.reportsDirectory=/tmp/<唯一目录>`，
  再把同一目录用 `--reports-dir` 指给 `node scripts/verify-coverage-scope.mjs`（它默认读
  `coverage/coverage-summary.json`）。`scripts/verify-stage.mjs` 已按这个方式实现。
- **陷阱**：`npm run test:coverage -- --coverage.reportsDirectory=…` **不能用**。
  npm 把附加参数追加到脚本字符串**末尾**，即落到 `…; if [ $cov -ne 0 ] || [ $scope -ne 0 ]; then exit 1; fi`
  **之后**，直接破坏 shell 语法。要用就绕开 npm script，走 `npx vitest run …`。
- **证据**：`PROGRESS.md` §2「注意事项」第三条；
  `scripts/verify-coverage-scope.mjs` 的失败文案里也复述了同一坑。

### C-3 派单书是人写的、会错 —— 先核前提再干活
- **现象**：四段改造里，**三份**报告开头都有「你给的前提里，N 处需要订正」一节（N = 1 / 3 / 3）。
  本轮又添一例：S6 的「超长工作区名」派单书写 **79 字符**，实测 `String.length === 89`（差 10，
  与报告里的 79 一致，说明错值从报告抄进了派单书）。
- **结论**：开工第一步是把任务书里的事实性断言逐条复现一遍，错了在报告开头写明订正，
  再按订正后的做。别一边怀疑一边照做。
- **证据**：`reports/2026-09-11-ui-revamp-stage3a.md` §1；`stage3b.md` §1；
  `tools/ui-probe/README.md` §3（S6 长度按实测记）。
- **重试**：不适用；这条是固定动作。

### C-4 写「怎么得到」比写「是多少」耐用
- **现象**：台账与注释里的绝对数字会随代码改动漂移，漂移后没人知道哪个还是真的。
- **结论**：记「怎么测出来」+「当时的实测值」+「口径」，别只记一个孤零零的数。口径变了，旧数就该作废。
- **证据**：`PROGRESS.md` §3「注释与台账里的数字会漂移」一节。

## D. 探针与读数

### D-1 `--window-size` 不够大、或格式写错 ⇒ hit-test **假红**
- **现象**：窗口比元素窄时元素落到视口外，`elementFromPoint` 拿不到命中（`hitTag=NULL`），
  探针把它判成「不可点」。**格式坑**：Chrome 的 `--window-size` **只认 `W,H`**，写成 `1600x1000`
  会被**静默忽略**并退回默认窗口。
- **结论**：`--window` 要比最宽采样档（默认 1200）大出余量，默认 `1600,1000` 即照此取；调高
  `--sn/--sw` 或加宽采样区间时必须同步调窗口。判别口诀：**只有 `unclickN` 一项集体变红、而矩形 /
  重叠 / 裁切 / 顶栏高度全正常时，先怀疑窗口尺寸**（后四类读数不看视口）。
- **证据**：`tools/ui-probe/README.md` §2.2 第 2 条。实测：本轮把格式误写成 `WxH` 时，面板 830–1200
  档全体误报不可点（260 处字段差异）；改成 `W,H` 后与 `/tmp` 原版逐档逐字段 **0 差异**。
- **重试**：不适用；这是跑探针的固定前置条件。

### D-4 探针读数**跨运行**有可测的非确定性 —— 别拿 1–2 档差异当回归
- **现象**：同一份 CSS、同一个脚本、同一台机器，两次运行之间也会有个位数的档对不上。实测标定
  （`--wsicon` 全扫 3857 档 × 14 字段）：`/tmp` 原版脚本「历史那次 vs 现在这次」有 **60 处**字段差异
  （`genLabShown` 48，`goneN` / `goneMidN` / `partRightN` 各 4），全部落在档界附近。
- **结论**：判回归看**结构性指标**——「0 档」「下界」「顶栏高集合」；不要拿单次运行里 1–2 档的差异
  当回归。要坐实某个差异，同条件复跑两次再下结论。
- **证据**：`tools/ui-probe/README.md` §4；本轮三方比对（仓库版 vs 原版本次复跑 = 0 差异；
  原版历史 vs 原版本次 = 60 处）。
- **重试**：不适用；这是读数的解读纪律。

### D-2 位置参数被**静默忽略**
- **现象**：参数解析只认 `--名` / `--名=值`，别的字符串直接丢掉且不报错。`node … probe.js now`
  会用默认 `--tag=probe` 覆盖上一轮产物，让人误以为「跑了新变体、结果没变」。
- **结论**：跑变体必须写 `--tag=`，并回看 stdout 里打印的 JSON 路径确认 tag。
- **证据**：`tools/ui-probe/README.md` §2.2 第 1 条。
- **重试**：不适用。

### D-3 探针量的是**工作树现状**，不是运行中的产物
- **现象**：CSS 从 `src/client/index.tsx` 的 `const CSS = [...]` 逐字解析——不 build 也能量到新样式；
  反过来**看不到** `client/client.js` 里的旧样式。
- **结论**：改完 CSS 立刻能量，这是它快的原因；要对照「运行中是什么样」，得用 `--css=<历史快照>`
  指过去（例：`/tmp/stage3/stage2-end.tsx`）。
- **证据**：`tools/ui-probe/README.md` §4。
- **重试**：不适用。
