# agent 协作层（入场必读）

给**下一个进这个仓库干活的人 / 子代理**看的。三分钟读完，然后按 §3 的顺序开工。

---

## 1. 三层存储：各放什么，谁写谁读

| 层 | 位置 | 持久性 | 可见性 | 谁写 | 谁读 |
|---|---|---|---|---|---|
| **会话上下文** | 主代理的对话历史 | **易失**（重启即失） | **私有**，主代理独有 | 主代理自己 | 只有主代理 |
| **仓库文件** | 本仓库工作树 | 持久（提交后永存） | 公共，主/子代理都能读写 | 主代理 + 子代理（限各自授权面） | 所有人 |
| **`dsh知识库/`** | `<工作区>/dsh知识库/`（**本仓之外**） | 持久 | 跨项目，可被 `kb_search` 检索 | 主代理 | 任何项目 |

**最关键的一条**：子代理**看不到主代理的对话历史**，它只拿到一份任务书。所以——任何子代理需要知道
的东西（需求、裁决、上一段末态、判据口径）**必须落在仓库文件里**；只存在于会话上下文里的信息，
下一个子代理必须重新推导一遍。

反面教材（本仓真实发生）：四段 UI 改造的探针脚本与 8 份报告全写进 `/tmp`，同一脚本被从头复活三次
（`gen.js` 13674B → 复制成 `stage3/gen.js` 同样 13674B → `gen3.js` 14489B → `gen4.js`），
约 14 万字节的实测证据随机器重启即失。**`/tmp` 不是共享层**，它是会话上下文的磁盘延伸。

## 2. 文件归属表（放错地方 = 下一个子代理找不到）

| 内容 | 放哪 | 谁写 | 备注 |
|---|---|---|---|
| 需求、裁决、验收标准 | `docs/spec-*.md` | 主代理（子代理**不改**） | 实现的唯一依据；改需求＝改这个文件 |
| 当前状态、已知风险、待办、决策记录 | `PROGRESS.md` | 主代理（子代理最多加一行指针） | 「现在是什么样」的唯一真源 |
| 任务报告、实测证据、未核实项 | `docs/agent/reports/` | 子代理 | **不要写 `/tmp`**；文件名按日期排序 |
| 可复用经验（尤其**已验证的负结果**） | `docs/agent/lessons.md` | 主代理 · 子代理可提议 | 一条一行到几行，带证据指向 |
| 工具、脚本、判据口径 | `tools/<工具名>/`（含自己的 README） | 建工具的人 | 口径的正文写在工具 README 里，脚本只是实现 |
| 程序化验收 | `scripts/verify-stage.mjs` | 主代理 · 子代理可改 | 见 §4 |
| 派单任务书 | `docs/agent/brief-template.md` | 主代理 | 模板；填好的任务书随报告归档 |
| 构建产物 | `lib/`、`client/`、`coverage/` | — | **不入库**（`.gitignore`） |

跨项目、别人也用得上的经验 → `dsh知识库/`（用 `kb_search` 查）；只对本仓库成立的 → 留在本仓库。

## 3. 入场必读顺序

按这个顺序读，**不要跳**。顺序是按「先知道自己不能碰什么，再知道要做什么」排的：

1. **`PROGRESS.md`** —— 先读 §1「当前状态」（现状与门禁数字）、§3「已知行为与风险」（哪些是**有意保留**
   的行为差异）、§5「待办」、§6「未做且明确不做的」。
   *为什么第一：这里写着「哪些是故意的」，不读就会把有意行为当 bug 修掉。*
2. **本段对应的 `docs/spec-*.md`** —— 需求与裁决的唯一依据。
   *为什么第二：需求口径以规格为准，不以任何报告或转述为准。*
3. **`docs/agent/lessons.md`** —— 已验证的负结果、阈值口径、踩过的坑。
   *为什么第三：这一步省掉的是「重新试一遍已知无效的方案」。*
4. **`docs/agent/reports/` 里最近一份**（按文件名日期排最后那份）—— 上一段末态、它的证据文件在哪、
   它列了哪些未核实项。
   *为什么第四：报告里明确写了「未核实」的，就是留给你的活。*
5. **`tools/ui-probe/README.md`** —— **只在涉及几何 / 宽度 / 顶栏 / 裁切时读**。它是判据口径的正文。
   *为什么最后：只有做这一类改动时才需要，别的任务读了是浪费。*

### 开工前自检

- 我能说出本段**授权改动面**（哪几个文件）吗？说不出就别动手。
- `docs/agent/lessons.md` 里有没有「别再试」的条目正好压在我准备做的方案上？
- 我打算产出的证据，**落在仓库里还是在 `/tmp`**？落 `/tmp` 的等于没产出。
- 我引用的每个数字，**来自哪个可复跑的产物文件**？（见 §5 第 5 条）

## 4. 门禁与验收

门禁共五项（`typecheck` / `lint` / `test` / `coverage` / `build`，口径见 `PROGRESS.md` §1 与 §2）。
子代理收尾**至少**要跑：

```bash
node scripts/verify-stage.mjs --allow <本段授权文件,逗号分隔>   # 范围守卫 + typecheck + lint + test + coverage
```

`verify-stage.mjs` 把主代理手工做的那套验收固化成一条命令：先查改动有没有跑到授权面之外（越界即红），
再依次跑四道门禁并出结论表；`--skip-coverage` 可跳过覆盖率（默认跑）。**`build` 不在它里面**——
build 会覆写 `lib/`、`client/` 这两个不入库的产物并影响运行中的实例，属于单独授权项。

**子代理不算完成的条件**：只交报告、没跑门禁；或跑了但没把**原始输出**贴出来。

---

## 5. 写作纪律（本仓血泪）

1. **数字必须来自可复跑的产物文件**，转述前对照原文。主代理在四段改造里转述子代理数字错了三次
   （口径混淆、拆分错位、基线值记错），每次都要下游重新核对。
2. **区分「实测」与「推断」**。「我推断不会更差」和「逐档 diff 证明没有任何一档变差」是两句话，
   报告里必须写清是哪一句。
3. **未核实项单独列**。"诚实清单"比"看起来很完整"有用。
4. **发现上游任务书有错，先订正再干活**，并在报告开头写「你给的前提里，哪几处需要订正」。
   派单书是人写的，会错（本仓已发生：名称字符数、基线数字、「本机必失败」的结论）。
5. **阈值/判据只在两个地方写**：口径正文（工具 README）与实现（脚本/样式）。第三处出现的阈值
   就是未来的 bug。
