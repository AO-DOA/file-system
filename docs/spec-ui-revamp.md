## 1. 需求

### R1 — 顶栏生成入口收编为「解读选择」

**现状**：`genItems` 只有三态 —— 目录节点恒 1 项（folder）、md 文件恒 `[]`（因为 md 不生成 L2/L3）、其它文件恒 `file` + `src`；「翻译」是独立按钮（`trBtn`）。

**目标**

| 项 | 行为 |
|---|---|
| 按钮文案 | 「生成解读」→「解读选择」 |
| 菜单项 | **按当前文件类型自动适配**，不给无关功能留位置 |
| 目录节点 | 目录概览 |
| 文件节点 | 文件摘要、源码注解 |
| 项目内非 `.book/` 的 md | **仅翻译** —— md 不生成 L2/L3，host 侧对 md 直接拒绝（`errGenMd`），故不列文件摘要/源码注解 |
| `.book/` 内的 md | 无生成入口（书库文档不是翻译对象） |
| 独立翻译按钮 | 取消（并入本菜单） |

**判据**：对目录 / 普通文件 / 项目内 md / 书库内 md 四类分别断言菜单项集合。

---

### R2 — 窄宽度图标化

**目标**：容器宽度不足时，三个按钮收成纯图标，且**全部保留 `Tooltip` + `aria-label`**（宿主纯图标交互的既有做法）。

| 按钮 | 图标 | 出处 |
|---|---|---|
| 解读选择 | `IconPlusOutline16` | 现状已是 `+` |
| 编辑 | `IconEditOutline16` | 现状已用该图标 |
| 保存 | `IconCheckOutline16` | DSH 的保存惯例：`ui-goal/GoalBar` 与 `ui-conversation/queue/QueueDock` 两处独立实例均用它 |

**阈值不写死**：以容器实测宽度驱动（见 §3「宽度档」），不用固定像素常量。

---

### R3 — 视图标签合并为「视图选择器」

**现状**：`viewer.modes` 按 `doc → annot → tr → source` 推入数组，渲染成一排胶囊（Pill）。

**目标**

| 项 | 行为 |
|---|---|
| 形态 | 单个按钮 + 悬停下拉，取代一排胶囊 |
| 默认 | 按钮文字「源码」，**同时默认展示源码界面** |
| 按钮文字 | **必须等于当前显示的视图名，不得分离**（用户明确要求） |
| 点击按钮 | 选中按钮所示视图（幂等；点什么就是选择看什么） |
| 悬停按钮 | 弹出下拉，列出**其余已具备**的视图 |
| 未生成的不列 | 不具备的视图（如未生成的摘要 / 未翻译的译文）不进下拉 |
| 顺序 | 源码 → 文件摘要 → 源码注解 → 文章翻译 |

**默认视图改为源码优先**：现状是 `hasDoc ? 'doc' : (hasSource ? 'source' : (hasDocSrc ? 'annot' : 'source'))`（有摘要就先显示摘要），本规格改为源码优先。

**判据**：`hasDoc` / `hasDocSrc` / `hasDocTr` / `hasSource` 的组合下，下拉项集合与按钮文字。

### R4 — 分栏

| 项 | 行为 |
|---|---|
| 入口 | 顶栏新增图标按钮 |
| 图标 | DSH 分栏字形（见 §2 的唯一例外） |
| 开启 | 把当前显示的视图**复制一份只读副本**到右侧 |
| 关闭 | **再点一次同一个按钮**即关闭右侧 |
| 只读 | 右侧不受任何控制，无编辑、无保存、无生成入口 |
| 独立性 | 左侧切换视图**只影响左侧**，右侧保持不动 |
| 分栏状态 | **按文件各自记忆**：当前文件开过分栏则左右分离；切到没开分栏的文件 / 文件夹则恢复全屏 |
| 宽度 | **可拖拽分栏**，拖拽比例同样按文件记忆 |

### R5 — 视图选择器搬到右侧、与「解读选择」同组（2026-09-13 用户裁决）

**现状**：视图选择器（R3 的产物）挂在顶栏**中列** `.fs-hbar-mid`（中列 = 视图选择器 + 路径），
右列是分栏 / 解读选择 / 未保存 / 编辑⇄保存。

**目标**

| 项 | 行为 |
|---|---|
| 位置 | 视图选择器由 `.fs-hbar-mid` 移到 `.fs-hbar-right`；中列自此**只剩路径**，不再持有任何按钮 |
| 右列次序 | 视图选择 → 解读选择 → 编辑⇄保存 → 分栏 |
| 交互语义 | **一字不改**：点击按钮主体 = `viewer.setMode(viewer.mode)`（同值 bail out、真 no-op）／外层 `.fs-viewwrap` 的 `onMouseEnter` 开下拉／`Menu` 传 `portal`／`closeOnPointerLeave`／刻意不挂 `Tooltip` |
| 元素 | **不新增任何 DOM 元素、不新增图标**：只改 JSX 顺序 + 随之失效的 CSS 与注释 |

**判据**：`.fs-hbar-mid` 内按钮数为 **0**；`.fs-hbar-right` 直接子项次序为
`视图选择 → 解读选择 → 编辑⇄保存 → 分栏`；视图选择器仍无 `.fs-btnlabel` 层、仍不挂气泡
（`tooltipLabel(viewBtn()) === null`）。

**代价（已实测、已裁决、已修）**：右列 min-content 多出一个约 68px 宽的胶囊 + 一处 6px gap ⇒ 纯搬
位置时右列「被整块裁」的下界由 **307 抬到 389**（面板；最坏场景 S2/S6），**破门禁 ≤360**。四条收纳
候选逐条实测后用户裁决 **候选 B（窄档把「分栏」整块收起）**，落地见下面的 **R5.1**：下界回到 **339**
（余量 21px），跨列 / 同列可见重叠仍 **0 档**、顶栏高恒 **{48}**。逐档 diff、单档取证与代价见
`docs/agent/reports/2026-09-13-view-picker-to-right.md`。

### R5.1 — 窄档收纳：分栏按钮整块让位（2026-09-13 用户裁决「候选 B」）

**要解决的问题**：R5 的搬入让右列 min-content 抬高约 74px ⇒ 纯搬位置态右列「被整块裁」的下界
**389**（门禁 ≤360，破线 29px）。中列已可被压到 0、左列已收到最小，右列每一项又都是功能键或状态
标记 ⇒ 只能减少**右列** min-content。

**做法**（只加一条容器查询规则 + 一个既有按钮上的类名，**不新增任何 DOM 元素**）：

| 项 | 值 |
|---|---|
| 规则 | `@container (max-width:620px){.fs-hbar-right > .fs-tipwrap:has(.fs-splitbtn){display:none}}` |
| 锚点 | 分栏按钮上的类名 `fs-splitbtn`（加在既有 `<Button>` 上）。样式表用 `:has()` 从它找到外层的 `.fs-tipwrap` **一起**藏 —— 只藏内层 `button` 会留下一个 0 宽却仍占一处 6px gap 的锚点层 |
| 阈值 620 | 端点＝分栏按钮**不再被裁**的容器宽 **573px**（面板 601 − `.fs-wrap` 左右内边距 28px；面板 ≤600 时它正是右列唯一被裁的那一项，`partRightN` 恒为 1），按本仓「约 8% 字体余量取整」的惯例 573 × 1.08 ≈ 619 ⇒ **620** |
| 生效边界（实测） | 面板 **≤648 收起、649 起显示**（`--dumpW=648` 的 `fs-splitbtn` raw 宽 **0**；`--dumpW=649` raw 宽 **36.0** 且与 vis 等宽 —— 显示时完整不被裁） |

**为什么不并进既有的 760 档**：两条规则读数**逐档完全相同**（3857 档 × 全部字段 **0 差异**），差别只在
「分栏入口消失」的面板区间 —— 并进 760 会把它从 ≤648 扩到 ≤788，窄档收纳没有理由多牺牲 140 档宽度。

**验收（`--wsicon`，7 场景 × 551 档 = 3857 档）**：右列被整块裁下界 **389 → 339**（✓ ≤360，余量 21px）；
跨列可见重叠 **0 档**、同列可见重叠 **0 档**、顶栏高恒 **{48}**；被裁合计 916 → **624 档**、右列部分裁切
1045 → **777 档**；相对搬位置态逐档 diff **变差 0 档 / 变好 1184 档**；分屏开启态（`--splitpane`）与默认态
**逐档逐字段 0 差异**；既有两档的切换点不受影响（`wsLabShown` 578/579、`genLabShown` 780/790）。产物
`out-final-lian3.json` / `out-final-lian3-split.json`。

**代价（已实测，属「已知边界，不修」）**：容器 ≤620（面板 ≤648）时**开/关分屏的入口随按钮一起消失** ——
`toggleSplit` 在源码里的**唯一调用点**就是这个按钮（菜单里没有第二条路），所以面板已经开着分屏时再把它
拖到 ≤648px 就关不掉了，得把面板拖宽才回得来。取舍与 §6「中列视图名」那条同源：窄档牺牲一个功能键。

## 2. 图标与元素来源（红线）

- 界面上出现的每个图标元素，**必须来自 `@deepseek-ai/dsh-client-ui-primitives`**（当前插件用到的 9 个图标都在该包的 `icons` 导出里）。
- **不得新增自绘 SVG 或装饰性字符符号。**
- **唯一例外（用户裁决）**：分栏字形。DSH 的分栏图标是 `ui-dockkit/src/components/TabPanel.tsx:42-48` 的 `SplitGlyph`，由 `PANEL_FRAME` 路径 + 一条竖线组成，文案为 `dock.splitPane`「分栏」。该组件与常量**均未 export**，且 dockkit 不在插件的 client 外置白名单（`tsdown.config.ts` 的 `CLIENT_EXTERNALS` 只认 react 系、cordis、`dsh-client-ui-slots`、`dsh-client-ui-primitives`、`dsh-client-web-react`、`dsh-client-runtime/client`）⇒ 插件无法 import。**经用户裁决：把它的 SVG 路径原样复制进插件。** 代价：插件内多一份副本，DSH 将来改图标时不会跟随——已知并接受。
- 纯图标交互**沿用本文件既有的 `<Button size icon title>` 写法并补 `aria-label`**（第三段 b 订正：原文写的「原生 `<button>` + `Tooltip` + `aria-label`」是我写错了）。依据：`Button` 已把 `title` 透传到原生属性，再包一层 `Tooltip` 会**出双气泡**；宿主 43 处 `<Button>` 全带 children、0 处自闭合——那描述的是**宿主**的按钮用法，不是本插件的：本文件的 `foldBtn` / `refreshBtn` 早已是自闭合的 `<Button … title={…} />`，R2 的三个按钮与 R4 的分栏按钮一律与它们保持一致。

## 6. 决策记录（用户当场裁决，落盘以防丢失）

| 决策 | 内容 | 理由 |
|---|---|---|
| 文件树角标 | 换成 `<Tag tone="quiet">`（纯文字无底色） | 官方组件；`quiet` 尺寸最接近现状（`neutral` 会宽 +27% 高 +19%），不挤占文件名 |
| 文件树蓝点 `.fs-docmark` | **保留现状自绘，不替换** | `StateDot` 没有等价态：`done`=绿、`ongoing`=蓝但**是 8 格点阵动画**、`idle`=灰，三选一都是语义降级；现状配色已走 `--dsw-alias-state-business-primary` 主题 token，并非硬编码 |
| 视图选择器点击 | 点击按钮主体 = 确认当前视图（**真 no-op**，不顺带 `setEditMode(false)`） | 用户明确要求；与「按钮文字必须等于当前视图」自洽 |
| 分栏图标 | 复制 DSH `SplitGlyph` 的 SVG 路径进插件 | 该字形未 export、dockkit 不在插件外置白名单，见 §2 |
| 分栏状态 | **按文件各自记忆**（切到未分栏的文件/文件夹即恢复全屏）；**可拖拽分栏** | 用户明确要求 |
| 窄宽度下「保存」 | 一起图标化（`IconCheckOutline16`） | 「编辑/保存」成对；只图标化编辑会导致窄屏改了没法存 |
| 极窄档策略 | **逐级收纳、保持单行**（先收按钮文字 → 再收工作区名；**禁止折行**） | 用户裁决。折行会让顶栏成倍变高（候选方案实测把顶栏高度从恒 48px 变成多个值），而收纳只需按容器宽度单调让位 |
| 工作区名阈值 | `@container (max-width:550px)`（第三段 b 由 470 上调） | 470 时工作区名在面板 499px 就恢复可见，而右列要到面板 535px 才完全不被裁 ⇒ **499–534 这 36 档**里保存按钮右边缘缺 17px（可点，视觉级残缺；基线合计 110 档）。提到 550 后该段残缺**归零**，中列被裁区间同时由 200–517 收到 200–358，右列整块裁下界不变（314，≤ 门禁 360） |
| 右列首档阈值 | `@container (max-width:760px)`（第三段 b 由 672 上调） | R4 的分栏按钮给右列多添一段文字：实测最坏场景（长工作区名 + 长路径 + 四字视图名 + 五字菜单项）在面板 **701–720** 会把中列挤到 0（视图名被裁 + 右列部分裁切）；收文字后该窗口整段消失，逐档 diff 确认 760 相对 672 **没有任何一档变差** |

**第三段实际实现（a：窄档收纳；b：R4 分栏 + 阈值收口）**

- **分栏复用同一套件，不新写渲染分支**：`FsPane({opened, viewer})` 无自身 state、`editMode === false` 时天然只读 ⇒ 右侧副本直接喂一个「视图类型冻结 + `editMode` 强制 false」的 viewer 给同一个 `FsPane`。
- **语义裁决（本段落地，用户确认）**：右侧副本 = **视图类型冻结、内容数据实时、强制只读**。
  - 冻结：视图类型在开启那一刻记进 `SplitState.mode`，左侧之后切视图**只影响左侧**；
  - 实时：数据字段（`source` / `docData` / `annotData` / `trData` / `fold`）**共用同一个 viewer**，左侧编辑保存后右侧内容跟着刷新；
  - 只读：`editMode` 恒 false ⇒ 没有编辑区、没有保存/生成入口（顶栏也只有一份）。
  - **不是历史快照** —— 右侧没有自己的一份数据副本。（原「设计骨架」里的「冻结快照」措辞不准确，此处订正。）
- **状态按文件 path 索引**：存在 `FsView` 层的 `Record<path, {on, mode, ratio}>`。开关与比例都按文件记忆；切到没开过分栏的文件/目录时查不到记录 ⇒ 自动恢复全屏。
- **分栏拖拽复用左侧树宽那套**（`.fs-split` + document 级 `mousemove`/`mouseup`，按 G-7 既有行为不做卸载清理），记的是**占比**（clamp 0.2–0.8）而不是像素，窗口缩放后按比例复原；右侧窗格是同为 `flex:1 1 0` 的外壳，占比 p 经 `flexGrow = p/(1−p)` 落到样式上。
