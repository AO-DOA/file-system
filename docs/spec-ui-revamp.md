## 1. 需求

### R1 — 顶栏生成入口收编为「解读选择」

**现状**：`genItems` 只有三态 —— 目录节点恒 1 项（folder）、md 文件恒 `[]`（因为 md 不生成 L2/L3）、其它文件恒 `file` + `src`；「翻译」是独立按钮（`trBtn`）。

**目标**

| 项 | 行为 |
|---|---|
| 按钮文案 | 「生成解读」→「解读选择」 |
| 菜单项 | **按当前文件类型自动适配**，不给无关功能留位置 |
| 目录节点 | 目录概览 |
| 文件节点 | 文件摘要、源码注解 |
| 项目内非 `.book/` 的 md | 在文件节点基础上追加 **翻译** |
| 独立翻译按钮 | 取消（并入本菜单） |

**判据**：对目录 / 普通文件 / 项目内 md / 书库内 md 四类分别断言菜单项集合。

---

### R2 — 窄宽度图标化

**目标**：容器宽度不足时，三个按钮收成纯图标，且**全部保留 `Tooltip` + `aria-label`**（宿主纯图标交互的既有做法）。

| 按钮 | 图标 | 出处 |
|---|---|---|
| 解读选择 | `IconPlusOutline16` | 现状已是 `+` |
| 编辑 | `IconEditOutline16` | 现状已用该图标 |
| 保存 | `IconCheckOutline16` | DSH 的保存惯例：`ui-goal/GoalBar` 与 `ui-conversation/queue/QueueDock` 两处独立实例均用它 |

**阈值不写死**：以容器实测宽度驱动（见 §3「宽度档」），不用固定像素常量。

---

### R3 — 视图标签合并为「视图选择器」

**现状**：`viewer.modes` 按 `doc → annot → tr → source` 推入数组，渲染成一排胶囊（Pill）。

**目标**

| 项 | 行为 |
|---|---|
| 形态 | 单个按钮 + 悬停下拉，取代一排胶囊 |
| 默认 | 按钮文字「源码」，**同时默认展示源码界面** |
| 按钮文字 | **必须等于当前显示的视图名，不得分离**（用户明确要求） |
| 点击按钮 | 选中按钮所示视图（幂等；点什么就是选择看什么） |
| 悬停按钮 | 弹出下拉，列出**其余已具备**的视图 |
| 未生成的不列 | 不具备的视图（如未生成的摘要 / 未翻译的译文）不进下拉 |
| 顺序 | 源码 → 文件摘要 → 源码注解 → 文章翻译 |

**默认视图改为源码优先**：现状是 `hasDoc ? 'doc' : (hasSource ? 'source' : (hasDocSrc ? 'annot' : 'source'))`（有摘要就先显示摘要），本规格改为源码优先。

**判据**：`hasDoc` / `hasDocSrc` / `hasDocTr` / `hasSource` 的组合下，下拉项集合与按钮文字。

---

### R4 — 分屏

| 项 | 行为 |
|---|---|
| 入口 | 顶栏新增图标按钮 |
| 图标 | DSH 分屏字形（见 §2 的唯一例外） |
| 开启 | 把当前显示的视图**复制一份只读副本**到右侧 |
| 关闭 | **再点一次同一个按钮**即关闭右侧 |
| 只读 | 右侧不受任何控制，无编辑、无保存、无生成入口 |
| 独立性 | 左侧切换视图**只影响左侧**，右侧保持不动 |
| 分屏状态 | **按文件各自记忆**：当前文件开过分屏则左右分离；切到没开分屏的文件 / 文件夹则恢复全屏 |
| 宽度 | **可拖拽分栏**，拖拽比例同样按文件记忆 |

## 2. 图标与元素来源（红线）

- 界面上出现的每个图标元素，**必须来自 `@deepseek-ai/dsh-client-ui-primitives`**（当前插件用到的 9 个图标都在该包的 `icons` 导出里）。
- **不得新增自绘 SVG 或装饰性字符符号。**
- **唯一例外（用户裁决）**：分屏字形。DSH 的分屏图标是 `ui-dockkit/src/components/TabPanel.tsx:42-48` 的 `SplitGlyph`，由 `PANEL_FRAME` 路径 + 一条竖线组成，文案为 `dock.splitPane`「分栏」。该组件与常量**均未 export**，且 dockkit 不在插件的 client 外置白名单（`tsdown.config.ts` 的 `CLIENT_EXTERNALS` 只认 react 系、cordis、`dsh-client-ui-slots`、`dsh-client-ui-primitives`、`dsh-client-web-react`、`dsh-client-runtime/client`）⇒ 插件无法 import。**经用户裁决：把它的 SVG 路径原样复制进插件。** 代价：插件内多一份副本，DSH 将来改图标时不会跟随——已知并接受。
- 纯图标交互沿用宿主做法：原生 `<button>` + `Tooltip` + `aria-label`（宿主 43 处 `<Button>` 全带 children、0 处自闭合，纯图标一律用原生 button）。

## 4. 验收

1. `npm run typecheck` / `npm run lint` / `npm test` / `npm run build` 全绿（当前基线：19 spec / 564 例）。
2. 窄宽度几何实测：沿用本轮已有的探针口径（元素矩形与 `overflow!=visible` 祖先裁剪盒求交），确认新增分屏与图标化后**跨列与同列均无重叠**，且**没有按钮被整块裁掉**（本轮已把该项列为必查，见 `PROGRESS.md` §5 #8）。
3. GUI 手工验收清单：四类节点的菜单项、窄宽度三按钮图标化、视图选择器（默认源码 / 悬停下拉 / 未生成不列）、分屏（开启 / 关闭 / 左侧切换不影响右侧 / 切文件恢复全屏 / 拖拽分栏）。
4. 改动后需 `npm run build` 并**重启 dsh web** 才生效（`README.md:147`）。
